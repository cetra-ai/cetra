# N9 — The packaging CI job

Read [README.md](README.md) first, especially § Design › Verification. Read `AGENTS.md` § CI
again.

**Goal:**
- Every pull request and every push to `main` runs a `packaging` job (D-N-13). The job runs
  `just check-packaging` on x86_64 Linux:
  1. `versions-check` and `helm-check`;
  2. the `x86_64-unknown-linux-musl` archive;
  3. the binary, install, image, compose and compose-S3 smoke tests.
- `ci-ok` requires the job.
- A composite action, `.github/actions/packaging`, installs the packaging tools. N10's release
  workflow reuses it, on Linux and macOS.

**Edit only:**
- `.github/actions/packaging/action.yml` (new);
- `.github/workflows/ci.yml`;
- `justfile`;
- `.github/README.md`;
- `AGENTS.md`.

**Commit:** `Run the packaging checks in CI`

**Tools:** actionlint 1.7.12 and zizmor 1.32.0 (`just check-workflows`), plus every tool of
N3–N7 for the local `just check-packaging` run.

## How it works

- **The recipe.** `check-packaging` has `versions-check`, `helm-check` and `js-install` as
  dependencies, lints `tools/packaging` with Biome (N2 added it to `biome.json`; no other CI job
  checks it), then calls the other recipes in order. It is the PR job's only `run:` step besides `assert-clean`.
  The kind install is not in PR CI; it runs in the release workflow.
- **The composite action.** Every step is a pinned action or a script.
  - Linux only: `apt-get install musl-tools`.
  - `taiki-e/install-action` (the SHA `ci.yml` already uses) installs `cargo-auditable@0.7.7`
    and `cargo-about@0.9.3`, prebuilt.
  - Linux only: `azure/setup-helm` v5.0.1 (helm v4.3.1).
  - Linux only: kubeconform v0.8.0, downloaded and checked against the SHA-256 in the release's
    `CHECKSUMS`. It is untarred into `/usr/local/bin` with `sudo`. Appending to `$GITHUB_PATH`
    from a composite action is a zizmor `github-env` finding.
  - Docker and docker compose come with GitHub's Ubuntu runners.
- **The linker.** `ci.yml` sets `RUSTFLAGS` to link with mold for every job. The packaging job
  sets `RUSTFLAGS: ""` so its archive is built exactly as the release workflow builds it, with
  the default linker. (`./.github/actions/rust` still installs mold; nothing uses it here.)
- **The job.** It uses the S3 compiler cache like the other Rust jobs (`environment: s3-cache`
  and the same inputs), because the release build is the slow part. Its timeout is 75 minutes.
  It runs on `ubuntu-24.04`, not `ubuntu-latest`, so the musl-tools package and the runner image
  stay predictable; N10 uses the same label.

## Files

### `.github/actions/packaging/action.yml` (new)

```yaml
name: Packaging tools
description: Install the release-build and packaging tools (musl-gcc, cargo-auditable, cargo-about; on Linux also helm and kubeconform)

runs:
  using: composite
  steps:
    - name: Install musl-gcc
      if: runner.os == 'Linux'
      shell: bash
      run: |
        set -euo pipefail
        sudo apt-get update -q
        sudo apt-get install -y -q musl-tools

    - name: Install cargo-auditable and cargo-about
      uses: taiki-e/install-action@b80e2bb2635f28eb98b9fce1e2f0887e1535c6b2 # v2.90.0
      with:
        tool: cargo-auditable@0.7.7,cargo-about@0.9.3

    - name: Install helm
      if: runner.os == 'Linux'
      uses: azure/setup-helm@9bc31f4ebc9c6b171d7bfbaa5d006ae7abdb4310 # v5.0.1
      with:
        version: v4.3.1

    - name: Install kubeconform
      if: runner.os == 'Linux'
      shell: bash
      # Checksums from the v0.8.0 release's CHECKSUMS file.
      run: |
        set -euo pipefail
        case "$(uname -m)" in
          x86_64) arch=amd64; sum=9bc2bffbf71f261128533edaf912153948b7ff238f9a531ae6d34466ec287883 ;;
          aarch64) arch=arm64; sum=1f53fc8e81258197a35e8603054162a5af1de8c5af13746c71ab680d9534ed87 ;;
          *) echo "no kubeconform for $(uname -m)" >&2; exit 1 ;;
        esac
        curl -fsSL -o "$RUNNER_TEMP/kubeconform.tar.gz" "https://github.com/yannh/kubeconform/releases/download/v0.8.0/kubeconform-linux-${arch}.tar.gz"
        echo "${sum}  $RUNNER_TEMP/kubeconform.tar.gz" | sha256sum -c -
        sudo tar -xzf "$RUNNER_TEMP/kubeconform.tar.gz" -C /usr/local/bin kubeconform
```

### `.github/workflows/ci.yml`

Add this job between the `e2e` job and `ci-ok`, with an empty line before it as between the
other jobs. The block below is at its final indentation (`packaging:` two spaces in, under
`jobs:`); paste it as is:

```yaml
  packaging:
    runs-on: ubuntu-24.04
    environment:
      name: s3-cache
      deployment: false
    timeout-minutes: 75
    env:
      # Build the archive exactly as release.yml does: the default linker, not ci.yml's mold.
      RUSTFLAGS: ""
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: ./.github/actions/rust # zizmor: ignore[self-repository] actionlint 1.7.12 rejects the $/ form
        with:
          cache: ${{ env.CI_CACHE_ALLOWED }}
          s3-access-key-id: ${{ env.CI_CACHE_ALLOWED == 'true' && secrets.S3_CACHE_ACCESS_KEY_ID || '' }}
          s3-secret-access-key: ${{ env.CI_CACHE_ALLOWED == 'true' && secrets.S3_CACHE_SECRET_ACCESS_KEY || '' }}
      - uses: ./.github/actions/js # zizmor: ignore[self-repository] actionlint 1.7.12 rejects the $/ form
      - uses: ./.github/actions/packaging # zizmor: ignore[self-repository] actionlint 1.7.12 rejects the $/ form
      - run: just check-packaging
      - run: just assert-clean
```

Then, in `ci-ok`'s `needs` list, add `packaging,` after `e2e,`.

## Verify

```bash
export PATH="$HOME/.local/share/nvm/v26.13.0/bin:$PATH"
just check-workflows
just check-packaging
just check
just assert-clean
```

- `just check-workflows` must print `No findings to report.` from zizmor and nothing from
  actionlint. A zizmor finding in your change is fixed in the YAML. Do not suppress it with an
  ignore comment beyond the `self-repository` ones shown, which the other jobs already use.
- `just check-packaging` takes 20–30 minutes locally. It ends with `compose-smoke: llmobs:dev
  passed (s3)`.
- After you push the branch, the PR's `packaging` job must pass and `ci-ok` must list it.
