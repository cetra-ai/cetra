# EA M4 — SIEM stream

**Summary.**
- This milestone streams audit records to an HTTPS endpoint: one destination per org, set by owners, and one for the instance, set by instance admins.
- Every 10 s, a task sends each destination's new records, oldest first, as a signed NDJSON batch. It moves a `seq` cursor on a 2xx and backs off on failures up to 1 h. It emails the owners (or the instance admins) once a destination has failed for 24 h.
- The status (last delivery, lag, last error, records lost to retention) shows on the Audit log page.
- Restore mode sends nothing.

## What it is, and what it is not

**What works when it's done:**
- An org owner sets an HTTPS URL and an optional header (for example `Authorization: Splunk <token>`) on the Audit log page.
  - cetra generates a signing secret and shows it once.
  - A test button sends one test line.
  - From then on, the org's records arrive at the endpoint within about 10 s, in order, at least once, signed with `X-Cetra-Signature` like alert webhooks.
- A failing endpoint is retried with backoff. After 24 h of failure, the owners get one email; a success resets that.
- The page shows the last success, the lag in records, the last error class, and whether records were purged before delivery.
- An instance admin does the same for the instance log.
- Lapses (`audit_log` lost) stop the stream; the destination is kept. Restore mode stops it.

**Out of scope:**
- several destinations per org;
- syslog, S3 or vendor-specific sinks (the design's non-goal);
- name resolution in the stream: ids only, as the design says.

## Decisions this plan relies on

| ID | Summary |
|---|---|
| D-EA-11 | One HTTPS NDJSON destination per org and one for the instance; at least once; cursor; signed; egress policy; backoff to 1 h; email after 24 h; restore mode sends nothing |
| D-EA-19 | Streaming stops on a lapse |
| D-EA-20 | The cursor is `seq` |
| D166 | The egress policy |
| D-I-2 | Secrets sealed with the instance key |

**Plan-level choices:**
- **P-1. The signing secret is generated by cetra** (32 random bytes, base64url, 43 characters) and shown once at creation or rotation, like API keys. It is not user-chosen. The dialog is `components/secret-dialog.tsx` `SecretDialog`.
- **P-2. One optional header** (name and value). The name is validated like alert channel headers (`HeaderName::from_bytes`, not reserved). The value is at most 1,024 bytes, sealed, and never returned. The URL must be `https`, at most 2,048 bytes, and is never returned; responses show `url_host` only.
- **P-3. The instance destination's failure email goes to the active instance admins** (`users WHERE is_instance_admin = 1 AND disabled_at IS NULL`).
- **P-4. Batch:** at most 500 records or 1 MiB (whichever comes first, always at least one record). The stream line format is fixed below.
- **P-5. Lost records.** `seq` is one sequence for every scope, so a scope's records are never contiguous and the task cannot infer loss from gaps. The retention purge flags it instead: when `purge_scope` deletes records of a scope whose destination's `cursor_seq` is below the highest deleted `seq`, it sets that destination's `lost_before_seq` to that `seq` in the same transaction. The status shows it until the destination is removed and created again: an edit or a secret rotation keeps the flag (the records are gone either way); only a new destination row, with its fresh cursor, starts unflagged.
- **P-6. Races.** `update_config` bumps `updated_at`. `mark_sent`, `mark_failed` and `mark_alerted` take the `updated_at` the task read, and update only `WHERE id = ? AND updated_at = ?`. A destination edited or deleted during a delivery is then left as the edit made it.
- **P-7. The test route reveals reachability only:** `{ "reached": bool, "status": Option<u16> }`. Connection errors and timeouts both read as not reached, so an owner cannot tell them apart to probe the network (alert channel tests have the same property; the docs note it).

**Edit:**

**Steps:**

1. **The stream line**, one JSON object per record:

   ```json
   {"id":"…","seq":42,"at":"2026-11-23T12:00:00.000Z","org_id":"…","project_id":"…","action":"member.role_changed","outcome":"success",
    "actor":{"kind":"user","id":"…","via":"session","credential_id":null},"target":{"kind":"user","id":"…"},
    "details":{…},"ip":"203.0.113.9","user_agent":"…"}
   ```

   - Absent values are JSON `null`. `target` is `null` when there is none, and `details` is the stored JSON parsed.
   - `stream.rs` has its own private `StreamRow` (every `audit_events` column) and query: `SELECT … FROM audit_events WHERE <scope> AND seq > ? ORDER BY seq ASC LIMIT ?`. It does not reuse M3's `read` module, which resolves names; the stream sends ids only.
   - Mapping: `at` (ns) → RFC 3339 with milliseconds, UTC (chrono, as `backup.rs:~549`); `actor` = `{kind: actor_kind, id: actor_id, via, credential_id}`; `target` = `{kind: target_kind, id: target_id}` when `target_kind` is set.
2. **`deliver_once(state: &AppState, now: i64) -> Result<Report, MetaError>`**, with `pub(crate) struct Report { pub(crate) sent: u32, pub(crate) failed: u32, pub(crate) skipped: u32 }` (destinations), logged at `debug` when non-zero:
   1. **Due destinations:** `stream_store::due`.
   2. **Gate:** skip a destination whose scope lacks the feature: `entitlements::of(state, org).allows(Feature::AuditLog)`, or `ee::audit::instance_gate(state, now)` (M3) for the instance. Skipping leaves the row unchanged.
   3. **Per destination**, at most 4 at a time (`buffer_unordered(4)`, as alerts):
      1. Open the config. Failure: `mark_failed(.., "the destination's settings cannot be read")` and continue.
      2. Read records after `cursor_seq`, up to 500.
      3. No records: do nothing.
      4. Build the body: lines until 500 records or 1 MiB, always at least one.
      5. Headers:
         - `content-type: application/x-ndjson`;
         - `X-Cetra-Signature`: `cetra_eval::sign_payload(&cetra_eval::Secret::new(config.secret.clone()), now / 1_000_000_000, &body)` (import as `cetra_eval::{Secret as EvalSecret, …}` if `crate::config::Secret` is in scope). `None` (an unusable key) is a permanent failure: `mark_failed` with "the signing secret is unusable", never a panic;
         - `alerts::deliver::DELIVERY_HEADER`: `<destination id>:<first seq>-<last seq>`;
         - the optional header.
      6. POST with `alerts::deliver::post` (made `pub(crate)` in this phase).
      7. **On a 2xx:** `mark_sent(read updated_at, last seq of the batch)`.
      8. **Otherwise:**
      - `attempts + 1`, `next_attempt_at = now + alerts::deliver::backoff_ns(attempts + 1)`, and an error class message:
        - "the endpoint answered <code>";
        - or `alerts::deliver::egress_error`'s message (made `pub(crate)` in this phase).
        - Then, when `failing_since <= now − 24 h` and `alerted_at` is null, call `mark_alerted` first and send the email (step 3) only when it returned `true`.
   4. **Logs** carry the destination id and `url_host` only.
3. **Email** `Email::AuditStreamFailing { scope_name: String, url_host: String, since_hours: u64, url: String }`:
   - `scope_name`: the org's display name, or "this cetra instance";
   - `url`: `<public_url>/<org slug>/settings/audit-log` or `<public_url>/admin/audit-log`.
   - Add it to `TEMPLATES`, `render`, `subject()` ("Audit stream failing for <scope_name>"), `template_name()` (`audit_stream_failing`) and the render tests, as `UsageNotice` is added.
   - Recipients: the org's active owners (as `entitlements/notices.rs` selects them, with `meta::members::org_members`), or the instance admins (P-3, a private query in `stream.rs`), via `mailer.send_in_background`. No mailer: nothing is sent, and `alerted_at` is still set, so a mailer configured later does not alert for that episode (as usage notices behave).
   - If the email tests count or list templates, extend them.
4. **`serve.rs`:**
   - `const AUDIT_STREAM_EVERY: Duration = Duration::from_secs(10);`
   - `spawn_audit_stream(state)`, shaped like `spawn_audit_purge` (interval, skip the first tick, log errors);
   - spawned inside the `if !state.config.restore_mode` block;
   - `restore_mode_skips_the_sending_and_dns_loops` gains one task (re-read its current count: other milestones may have changed it), with its doc list.
5. **`audit/retention.rs` `purge_scope`:** change each batch, inside its write closure, to:
   1. `SELECT seq FROM audit_events WHERE at < ? AND org_id IS ? ORDER BY seq LIMIT ?`;
   2. when the batch is empty, stop;
   3. `DELETE FROM audit_events WHERE at < ? AND org_id IS ? AND seq <= ?` with the batch's last `seq`, which deletes exactly those rows;
   4. `stream_store::flag_lost(conn, org, last_seq)` with `org: Option<OrgId>` (bind NULL for the instance), in the same transaction (P-5).

**Tests** (`ee/audit/stream.rs`, `test_support::hook_receiver::HookReceiver`, `TestApp::with_config(|c| c.security.allow_private_network_egress = true)` and a manual clock, as `alerts/deliver/tests.rs` does):
