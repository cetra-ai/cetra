# S5 — The control plane's user calls fall back to the email (R21)

**Commit subject:** `Find a control-plane user by email when no identity names it`

**Goal:** `POST /api/internal/v1/users/{revoke,disable,delete}` take the user's email next to the subject. When no identity at `entitlements.control_plane_provider` has the subject, the routes look the user up by the normalized email, as `memberships/lookup` already does (D-P-40), so a Q user who created an org through Q but never logged into the cell is still revoked, disabled or deleted there (D-S-9). An email whose user is linked to the control plane's provider under another subject is not that user and is treated as unknown.

Replace the struct and its doc comment with:

```rust
/// Body of the `users` routes (D-P-39, D-S-9): the user's subject at the control plane's
/// provider, and its email for a user the subject does not find.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, ToSchema)]
#[serde(deny_unknown_fields)]
pub struct InternalUserRef {
    /// The OIDC subject (`identities.subject`) of the user at `entitlements.control_plane_provider`.
    pub subject: String,
    /// Email, normalized like every email (D136). Used only when no identity has the subject,
    /// and then only for a user with no identity at that provider (D-S-9).
    pub email: String,
}
```

The field is required: the control plane always sends it (R21). There is no other caller (check with `grep -rn "InternalUserRef" crates tools`; only `internal.rs`, `openapi.rs` and `internal_users.rs` may appear).

   enum Matched {

3. Replace `managed_user` (with its doc comment) by:

   ```rust
   /// The user the call names, or `None` when there is none. The subject is looked up first,
   /// at `entitlements.control_plane_provider`. Without such an identity, the normalized email
   /// names a user only when that user has no identity at that provider: one linked under
   /// another subject is another control-plane account (D-S-9). The email is validated only
   /// when it is used, as `memberships/lookup` does. The control plane never manages an
   /// instance admin, so one is refused.
   async fn managed_user(
       state: &AppState,
       body: &InternalUserRef,
   ) -> Result<Option<(Uuid, Matched)>, ApiError> {
       let reader = state.meta.reader();
       let provider = &state.config.entitlements.control_plane_provider;
       let found = match identity_user(reader, provider, &body.subject).await? {
           Some(user_id) => Some((user_id, Matched::Subject)),
           None => {
               let email = normalize_email(&body.email)
                   .map_err(|_| field_error("email", "invalid email"))?;
               match user_by_email(reader, &email).await? {
                   Some(user)
                       if !user_identities(reader, user.id)
                           .await?
                           .iter()
                           .any(|linked| linked == provider) =>
                   {
                       Some((user.id, Matched::Email))
                   }
                   _ => None,
               }
           }
       };
       let Some((user_id, matched)) = found else {
           return Ok(None);
       };
       let Some(user) = user_by_id(reader, user_id).await? else {
           return Ok(None);
       };
       if user.is_instance_admin {
           return Err(ApiError::Forbidden {
               code: ProblemCode::Forbidden,
           });
       }
       Ok(Some((user_id, matched)))
   }
   ```

   If `state.meta.reader()` returns a reference that `identity_user`, `user_by_email`, `user_identities` and `user_by_id` all accept (they take `&SqlitePool`), the code compiles as written; `lookup` in `internal_members.rs` uses the same `let reader = state.meta.reader();`. If `user_by_email` returns a row type other than one with `.id: Uuid`, adapt only the field access.
