# S2 — Instance admins keep their password under `disable_password` (R13)

**Commit subject:** `Let instance admins use their password when password login is off`

**Goal:** with `auth.disable_password = true`, an instance admin can still log in with a password, change it, and set it from a reset link; everyone else is refused as before (D-S-3). The login refusal moves after the password check, so it reveals nothing to someone without the password. `GET /api/auth/config` keeps `password_enabled: false` (D-S-4).

## Steps

**Anchors.** `if state.config.auth.disable_password {` appears in five handlers of `routes/auth.rs`, and the org SSO block in both `login` and `reset_password`. Every Edit in steps 1 and 2 must include enough surrounding lines of the named function (its signature or the lines just before and after) to be unique; when an Edit reports a non-unique match, widen it, never use `replace_all`.

### 1. `login` (`routes/auth.rs`)

1. Delete the first block of `login`:

   ```rust
       if state.config.auth.disable_password {
           return Err(ApiError::Forbidden {
               code: ProblemCode::Forbidden,
           });
       }
   ```

2. Right after the existing org SSO block

   ```rust
       // Checked after the password verifies, so a wrong password reveals nothing (D-P-58).
       if crate::ee::org_sso::enforces(&state, &user.email) && !user.is_instance_admin {
           return Err(ApiError::Forbidden {
               code: ProblemCode::SsoRequired,
           });
       }
   ```

   insert:

   ```rust
       // Password login is off for everyone but instance admins, who are never linked to
       // an identity (D148, D-S-3). Checked after the password verifies, like the block above.
       if state.config.auth.disable_password && !user.is_instance_admin {
           return Err(ApiError::Forbidden {
               code: ProblemCode::Forbidden,
           });
       }
   ```

Everything else in `login` stays: the rate limit, `requires_sso`, the uniform 401s, lockout, the email verification check, the rehash. Under `disable_password` a non-admin's wrong password now answers 401 and counts toward lockout, like any password login (D-S-3).

### 2. `reset_password` (`routes/auth.rs`)

1. Delete its block

   ```rust
       if state.config.auth.disable_password {
           return Err(ApiError::Forbidden {
               code: ProblemCode::Forbidden,
           });
       }
   ```

   (the one right after the `ip_forms` rate limit, before `if !is_opaque_token(&body.token)`).

2. Right after the org SSO block of `reset_password`

   ```rust
       if crate::ee::org_sso::enforces(&state, &user.email) && !user.is_instance_admin {
           return Err(ApiError::Forbidden {
               code: ProblemCode::SsoRequired,
           });
       }
   ```

   insert:

   ```rust
       // Only instance admins set a password while password login is off (D-S-3); the token
       // stays unused.
       if state.config.auth.disable_password && !user.is_instance_admin {
           return Err(ApiError::Forbidden {
               code: ProblemCode::Forbidden,
           });
       }
   ```

`forgot_password`, `signup` and `setup` keep their `disable_password` refusals unchanged (D-S-3).

### 3. `change_password` (`routes/me.rs`)

Replace

```rust
    if state.config.auth.disable_password {
        return Err(ApiError::Forbidden {
            code: ProblemCode::Forbidden,
        });
    }
```

with

```rust
    // Instance admins keep their password while password login is off (D-S-3).
    if state.config.auth.disable_password && !row.is_instance_admin {
        return Err(ApiError::Forbidden {
            code: ProblemCode::Forbidden,
        });
    }
```

2. New `instance_admins_log_in_with_a_password_when_password_login_is_off`:
