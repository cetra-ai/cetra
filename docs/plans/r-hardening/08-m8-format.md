# R · M8 — Format stability

The eighth and last milestone of track R (`00-design.md` § M8, decisions D-R-12 and D185, refined by D-R-26 to D-R-32). From the first public release tag on, a data directory written by one release must open with every later one, and a directory written by a *newer* binary must be refused by an older one without being touched. M8 builds the tools that make both checkable, and lands before that tag:
- **Version markers** where a persisted format has none: the `catalog.db` data-directory marker, a header in every WAL segment, a `llmobs.format_version` key in every Parquet file.
- **Clean refusals** for a newer directory, a newer WAL segment and an unknown catalog migration. Today an older binary truncates a newer WAL tail as if it were torn, or quarantines a newer Parquet file as corrupt.
- **Golden data directories**, small, generated by one tool from the current build, committed, and opened by a test with the current code, whose reads must equal the ones recorded when the directory was written.
- **A release rule**: every stable release adds a golden directory and keeps the old ones (the 0.x ones until 1.0, D-R-12).
- **Catalog migration tests** and **pins** for the read cache and object layout.

Sub-phases R8.1–R8.8, one commit each.

**Before the first public tag there is no format constraint** (D185, `AGENTS.md`). M8 changes formats freely, including the WAL segment layout (R8.3). Directories written before M8 are not migrated: the new code refuses them with a clear message (R8.2, D-R-27).

## What exists today (checked on `main` 30bed18, and `claude/r-m3-fuzzing`)

Every persisted format, its version marker, and what a reader does with a version it does not know.

| Format | Where | Marker today | Unknown or newer input today |
|---|---|---|---|
| **WAL segment** | `wal/<table>/<first seq, 20 digits>.wal` (`wal/mod.rs::segment_name`) | **None.** No segment header: a segment is records only (`wal/segment.rs::SegmentWriter::create` writes nothing). The spec 12 sentence "the WAL carries a version byte in each segment header" is not true. | A record with `kind != 1` is `Decoded::Invalid` (`wal/record.rs`). In the **last** segment `replay.rs::scan_segment` treats that as a torn tail and **truncates it** (`truncate_tail`): an older binary erases a newer binary's records. Earlier segments: `WalError::Corrupt` (the open fails), or a skip with `--wal-skip-corrupt`. A payload that is not one batch of the table's current schema is `Corrupt` too (`read_batch`). |
| **WAL record** | inside a segment, `wal/record.rs` | `kind` byte (1 = row batch, 2 reserved). Header 17 bytes (`HEADER_LEN`): `u32 payload_len`, `u32 crc32c`, `u64 seq`, `u8 kind`. Payload: an Arrow IPC stream, LZ4-frame compressed, one batch. Cap: `MAX_PAYLOAD` 256 MiB. | As above. On `claude/r-m3-fuzzing` (to merge before M8): `MAX_DECODED_BYTES` 1 GiB declared decompressed bytes per record, LZ4 ratio bound 256 plus 64 bytes of slack per buffer, **LZ4_FRAME only** (D-R-25 there). These are part of what a v1 record is. |
| **Parquet file** | `objects/tables/<table>/project=<id>/day=<YYYY-MM-DD>/<level>-<uuidv7>.parquet` (`objects.rs::table_file_path`) | KV metadata written by `parquet.rs::file_metadata`: `llmobs.table`, `llmobs.schema_version` (`"1"`), `llmobs.level`, `llmobs.min_time`, `llmobs.max_time`, `llmobs.min_ingest_time`, `llmobs.max_ingest_time`. **`llmobs.schema_version` is the row normalization version (spec 01), not a file-format version.** | **No code reads any of these keys** (the catalog holds the same bounds). Extra columns are ignored by DataFusion's schema adapter (spec 03 §3). A changed column type or a missing required column is a read error, which makes the file a suspect (`verify.rs::may_be_corrupt`); `verify_file` then finds it corrupt and **quarantines it**: a newer file that is not corrupt would be hidden from queries. |
| **`catalog.db`** | `<data_dir>/catalog.db`, SQLite WAL mode, `synchronous=FULL` | `sqlx` migrations `0001`–`0007` in `crates/storage/migrations/catalog/`, tracked in `_sqlx_migrations` (version, checksum). Copies keep their number: `catalog.db.pre-m<N>` (`catalog/db.rs::pre_migration_copy`, D-N-22). | An applied migration the binary does not know: `sqlx` `MigrateError::VersionMissing`, so the open fails with `CatalogError::Migrate` and a message about a missing migration, before any write (no pre-migration copy: `applied >= expected`). An edited migration file: `VersionMismatch` (checksum). A TEXT value the binary does not know (`data_files.state`, `table_name`, `deletions.kind`, `projects.state`): `CatalogError::Corrupt` while loading. **No marker for a change that adds no migration**, such as a new meaning for a column. |
| **Catalog snapshot** | `Storage::snapshot_catalog` (`snapshot.rs`), `VACUUM INTO` | Same as `catalog.db`. | Same. The backup `manifest.json` is track N's, not storage's. |
| **Object paths** | `data_files.path` (relative path, never parsed), `media/<project>/<sha256 hex>` (`objects.rs::media_path`) | None. | A path is opaque to readers; a *new layout* only applies to new files. |
| **Media blob** | `objects/media/...`, the raw bytes; `media` table holds mime, size, times | None. | None needed: the blob is the bytes. |
| **S3 read cache** | `cache/<file name>/size` (8 bytes LE size, then CRC-32C: `SIZE_FILE_LEN` 12, D-R-21) and `cache/<file name>/<block index>` (block bytes then CRC-32C) (`read_cache.rs`) | None. Block size `BLOCK` = 1 MiB is implicit. | A `size` file that does not parse drops the whole directory, a bad block CRC drops the block: the cache heals itself. **A changed `BLOCK` would not be detected**: old blocks keep valid CRCs and would be served at the wrong offsets. |
| **`LOCK`, `tmp/`, `admin.sock`** | | no content that survives a restart | not formats |
| **`meta.db`, `secret.key`, backup `manifest.json`** | server and track N | their own | out of M8 (§ Requests) |

Two consequences drive the design:
1. An older binary can **destroy** newer data in two places (WAL tail truncation, quarantine of a newer Parquet file), not only fail to read it. A refusal must therefore come before either can happen: at the first step of `Storage::open`, from a marker in `catalog.db`.
2. `Storage::open` always opens `catalog.db` first (`open_shared` → `Committer::open` → `open_catalog_db`, also for `Maintenance::open`), so one marker there covers every surface of the directory.

## The design

**One number, three places** (D-R-26). `FORMAT_VERSION: u16 = 1` in a new `crates/storage/src/format.rs`. It is the format version of the whole data directory: it changes when *any* persisted surface changes in a way that is not additive. It is written to:
- `catalog.db`'s `PRAGMA user_version` (the directory's **high-water mark**: the highest format any file of the directory may use; a binary writes it before it first writes anything in a newer format, and never lowers it);
- every WAL segment, in an 8-byte header;
- every Parquet file, as KV key `llmobs.format_version`.

`llmobs.schema_version` keeps its meaning (row normalization). The read cache and `tmp/` carry no version (D-R-32).

**Open order.** `open_catalog_db`: connect, read `user_version`; if it is above `FORMAT_VERSION`, fail with `CatalogError::FormatTooNew`. This is before `pre_migration_copy` and before the migrations, so a newer directory is not touched. Then migrate (a migration the binary does not know becomes `CatalogError::SchemaTooNew`). Then, if `user_version` is 0: an empty catalog is a new directory and gets stamped; a non-empty one is a pre-release directory and fails with `CatalogError::PreFormat`. The WAL is read after the catalog (`lib.rs::open_inner`, `recover_tables`), where each segment header is checked.

**What is a format change** (D-R-12, here made concrete):
- **Not a format change:** a new nullable Parquet column; a `catalog.db` migration that only adds (`CREATE TABLE`, `CREATE INDEX`, `ALTER TABLE … ADD COLUMN` with a default or nullable); new config keys.
- **A format change (bump `FORMAT_VERSION`):** a new or changed WAL `kind`, header or compression; a changed IPC schema of a WAL payload; a changed Parquet column type, sort order, KV key meaning or file layout; a renamed or re-typed catalog column, a dropped table, an `UPDATE` of existing rows, a new value of a TEXT enum column (`state`, `kind`, `table_name`); a changed object path layout; a changed checksum; a changed read-cache block size.

**What a release that changes a format must do** (D185, D-R-12): bump `FORMAT_VERSION`, keep a reader for what the previous release wrote (replay of older WAL segments before writing the new ones; Parquet readers for older files, which are never rewritten at upgrade, `docs/self-hosting/upgrade.md`; a catalog migration), test it by the previous releases' golden directories, and add a line to `CHANGELOG.md` § `### Upgrade notes`. The *first* bump is the first time a reader for an older version exists: R8.2 and R8.3 write the checks as "equal to `FORMAT_VERSION`", and that change turns them into a supported range. M8 does not add range code that has nothing to read.

**Downgrade** (D-R-27): a binary that sees a newer marker, a newer WAL header version or a migration it does not know refuses to open, names what it found and what it reads, and changes nothing in the directory. `--wal-skip-corrupt` never bypasses these. There is no downgrade path; the way back is the pre-upgrade backup (`docs/self-hosting/upgrade.md`).

**Golden directories** (D-R-29, D-R-30). `fixtures/storage/golden/<version>/` is a plain directory tree (no archive, so no new dependency), written by the ignored in-crate test `golden_tests::write_golden_dir` through `just golden-dir <version>`. `fixtures/storage/golden/RELEASES` lists the released versions. Each directory holds a real data directory (`catalog.db`, `wal/`, `objects/`, a small `cache/` entry) and `expected.json`. A test opens a temp copy of each one with the current code and compares its reads with `expected.json`.

  - `fixtures/storage/golden/` (new) and `.gitattributes` (new, root, one line);
  - `justfile` (R8.6, R8.8);
  - `docs/spec/03-storage.md`, `docs/spec/12-operations.md`, `docs/research/storage/hardening.md`;
  - `AGENTS.md` (Commands, Tests, Layout: R8.6, R8.8).

  Not edited: `docs/self-hosting/` (track N's), `llmobs-core`, the server, the CLI, `tools/packaging/`, `.github/`. Changes there are requests (§ Requests).
- **No new dependency.** `sqlx`, `serde_json`, `tempfile`, `sha2`, `parquet`, `arrow` are already dependencies or dev-dependencies of `llmobs-storage`. Check `Cargo.toml`; if a dev-dependency is missing, add it with `{ workspace = true }` and report it.
- **No compatibility layers** (`AGENTS.md`): the pre-M8 WAL layout and pre-M8 directories get no reader. `FORMAT_VERSION` checks are equalities until a real second version exists.
- **Errors** are `thiserror` variants of the crate's enums (`CatalogError`, `WalError`). They name versions and file names, never project ids, row content or ids of data (privacy rule). The messages below are the wording to use.
- **Tests** may `unwrap` and `expect` with a message that says what was expected.
- **CHANGELOG:** M8 adds no line: everything it changes is pre-release behaviour (D185). The first release's `### Upgrade notes` belong to the coordinator.
- **Report at the end of each sub-phase:** what was done; deviations from this plan and why; sizes and counts where the plan says to measure; run time of each new test; anything left undone or unverified.

### Names used throughout

- **`FORMAT_VERSION`**: `crate::format::FORMAT_VERSION: u16 = 1`.
- **Golden projects** `P1` = `018f6b4e-7c1a-7c1a-8c1a-0000000000a1`, `P2` = `…0000000000a2`, `P3` = `…0000000000a3` (P3 is dropped).
- **Golden days**: `D0` = 2026-02-01, `D1` = 2026-02-10, `D2` = 2026-02-11 (UTC). Times in ns since the Unix epoch, as everywhere.
- **`dir_digest(dir)`**: a test helper (R8.2, in `format.rs` under `#[cfg(test)] pub(crate) mod tests_support`) that returns a sorted `Vec<(relative path, sha256 hex)>` of every regular file under `dir`, ignoring `LOCK`, `catalog.db-wal` and `catalog.db-shm`. Tests of refusals compare it before and after the failed open.

From the first public release (D185), a data directory written by any release must open with every later one, and a directory written by a newer binary must be refused by an older one without being changed. Before that release there is no constraint.

Downgrading is not supported: the way back is the backup taken before the upgrade (12 § Upgrades).

**Golden directories.** `fixtures/storage/golden/<version>/` is a small data directory written by the release's own build (`just golden-dir <version>`), with `expected.json`: the answers of the public reads. A test opens a copy of every one with the current code and compares. `fixtures/storage/golden/RELEASES` lists the released versions. ## R8.2 — The data-directory marker in `catalog.db`

Commit: `storage: refuse a data directory of a newer format, stamp new ones (R8.2)`

Depends on: R8.1.

### New `crates/storage/src/format.rs`

```rust
//! The format version of the data directory (spec 03 § 11, D-R-26).

/// The format version this build writes and reads.
///
/// It changes when any persisted surface changes in a way that spec 03 § 11
/// calls a format change. Today a reader accepts exactly this version; the first
/// bump adds the readers of the previous one.
pub(crate) const FORMAT_VERSION: u16 = 1;
```

`lib.rs`: `pub(crate) mod format;` next to the other modules. The `tests_support` module with `dir_digest` (see Names) lives in the same file.

### `error.rs`: three `CatalogError` variants

```rust
/// The directory was written by a newer format (spec 03 § 11).
#[error("this data directory has format version {found}, newer than the {supported} this build reads; run the newer release, or restore the backup taken before the upgrade")]
FormatTooNew { found: i64, supported: u16 },
/// A directory from before format versions existed (pre-release).
#[error("this data directory has no format version: it was written before format versions were introduced; create a new data directory")]
PreFormat,
/// `catalog.db` has applied a migration this build does not have.
#[error("catalog.db has applied migration {version}, which this build does not have; run the newer release, or restore the backup taken before the upgrade")]
SchemaTooNew { version: i64 },
```

With doc comments on the fields, like their neighbours. `OpenError::Catalog` is `#[from] CatalogError`, so they reach the caller unchanged.

### `catalog/db.rs::open_catalog_db`

New order, after `connect()`:

1. `let marker = read_user_version(&mut connection).await?;` (`PRAGMA user_version`, an `i64`).
2. `if marker > i64::from(FORMAT_VERSION)` return `FormatTooNew { found: marker, supported: FORMAT_VERSION }`. **Before** `applied_version`, `pre_migration_copy` and `migrate`: nothing is written. (`connect()` itself may create `catalog.db-wal`/`-shm`; `dir_digest` ignores them.)
3. `applied`, `expected`, `pre_migration_copy` and `migrate` as today, with one change: `MigrateError::VersionMissing(version)` becomes `CatalogError::SchemaTooNew { version }`; every other migrate error stays `CatalogError::Migrate`.
4. `if marker == 0`: if `catalog_is_empty(&mut connection).await?`, run `PRAGMA user_version = <FORMAT_VERSION>`; otherwise return `Err(PreFormat)`.

`catalog_is_empty`: true when `data_files`, `deletions`, `media`, `projects` and `retention_watermarks` have no row, and `table_state` has no row with `flushed_seq > 0` (one query with an `EXISTS` per table). The empty case matters: a process that dies between the migrations and the stamp of a new directory must be able to open it again.

`PRAGMA user_version = N` takes an integer literal, not a bound parameter: `format!` the `u16` constant into the SQL. It runs on the single connection outside any transaction, and `synchronous=FULL` makes it durable.

**Why `user_version` and not a table:** it is in the SQLite file header, so it can be read before any migration, it survives `VACUUM INTO` (snapshots and pre-migration copies keep it; tested below), and `sqlite3 catalog.db 'PRAGMA user_version'` shows it to an operator.

## R8.3 — The WAL segment header

Commit: `storage: add a format header to every WAL segment (R8.3)`

Depends on: R8.2, and M3 merged. **A format change, allowed before the first release** (D-R-12, D-R-28): segments written before this commit have no header and are refused (`NotAWalSegment`).

### Layout (spec 03 § 1)

An 8-byte header, then the records, which are unchanged:

```
[0..4)  magic   b"LWAL"
[4..6)  u16 LE  format version (FORMAT_VERSION)
[6..8)  u16 LE  flags, must be 0
[8..)   records (u32 payload_len | u32 crc32c | u64 seq | u8 kind | payload)
```

The record layout is **v1 as it stands after M3**: payload at most 256 MiB, at most 1 GiB declared decompressed bytes per record, each LZ4 buffer's declared size at most 256 times its compressed length plus 64, LZ4-frame compression only, `kind` 1 only. Offsets in errors and logs stay file offsets (they now start at 8).

### `wal/segment.rs`

```rust
/// First bytes of every segment.
pub(crate) const SEGMENT_MAGIC: [u8; 4] = *b"LWAL";
/// Length of the segment header.
pub(crate) const SEGMENT_HEADER_LEN: usize = 8;

/// The header this build writes.
pub(crate) fn segment_header() -> [u8; SEGMENT_HEADER_LEN];

/// What a segment's first bytes say.
#[derive(Debug, PartialEq, Eq)]
pub(crate) enum HeaderState {
    /// A complete, supported header.
    Valid,
    /// Fewer than `SEGMENT_HEADER_LEN` bytes, all equal to the start of the header:
    /// a crash created the file before its header was complete.
    Torn,
}

/// Checks `bytes` (the whole file, or its first bytes) against the header.
///
/// Errors: `WalError::Header` with `NotAWalSegment` (the magic differs, or the file
/// is shorter than the header and is not a prefix of it), `NewerFormat { found }`
/// (the version is not `FORMAT_VERSION`; no older version exists) or `UnknownFlags`.
pub(crate) fn check_header(table: &'static str, segment: &str, bytes: &[u8]) -> Result<HeaderState, WalError>;
```

`SegmentWriter`:
- `create` writes the header with `write_all` through `fs::File` right after opening (the `WalWrite` hook is **not** consulted: it models record writes; the creation faults are the open and `WalSegmentDirSync`). `len` starts at `SEGMENT_HEADER_LEN`.
- `open_segment` reuses an existing file only when it holds no record: its length is at most `SEGMENT_HEADER_LEN` and its bytes are a prefix of the header. It truncates it to 0 and writes the header again. Anything else is the error it is today.
- New `pub(crate) fn has_records(&self) -> bool { self.len > SEGMENT_HEADER_LEN as u64 }`.
- No separate fsync of the header: the next `fdatasync` of the segment covers it, and a segment is fsynced before a newer one exists (D-R-20).

`wal/writer.rs`: the places that meant "empty segment" by `len() == 0` now mean "holds no records":
- `run`: `let wanted = segment.len() > 0;` becomes `segment.has_records()`.
- `remove_stray_segment`: the file may be removed when its length is at most `SEGMENT_HEADER_LEN`. The "the segment is not empty" error stays for longer files.
- the test near `writer.rs:1327` (`entry.metadata().unwrap().len() > 0`) becomes `> SEGMENT_HEADER_LEN as u64`; every other test that counts bytes or non-empty segments is found by `grep -n "len()" crates/storage/src/wal/writer.rs` and fixed the same way.

`wal/replay.rs::scan_segment` (it has `table` and the segment name through `Scan`):
1. Call `check_header(scan.table.name(), scan.name, bytes)` first.
   - `Err` → return it. **Header errors are never skipped**, whatever `skip_corrupt` says, and never truncated.
   - `Ok(Valid)` → start the loop at `offset = SEGMENT_HEADER_LEN`.
   - `Ok(Torn)` (a zero-length file is `Torn`) → if `scan.is_last`: `truncate_tail(path, 0, bytes.len(), scan)` and `return Ok(false)` (the `create` that follows rewrites the file). If it is not the last segment: `Err(corrupt(scan, 0))` (a segment is fsynced before a newer one exists, D-R-20, so this is real damage; `skip_corrupt` may skip it through `skip_rest` as for any bad non-final segment).
2. Everything after is unchanged.

`recover_table` and `lib.rs` need no change: the `SegmentWriter::create` after replay already starts a fresh segment. `lib.rs::replay_error` leaves `WalError::Header` as `OpenError::WalReplay`.

## R8.6 — The golden directory generator

Commit: `storage: generate a golden data directory from the current build (R8.6)`

Depends on: R8.2–R8.5.

### New `crates/storage/src/golden_tests/` (`#[cfg(test)] mod golden_tests;` in `lib.rs`)

```
golden_tests/mod.rs      tests, shared constants, check_dir (R8.7)
golden_tests/build.rs    the scenario that writes a data directory
golden_tests/dump.rs     the reads that become expected.json
```

Why in the crate and not in `tests/`: the scenario needs `test_support` (`span_row`, `score_row`, `span_rows`, `score_rows`, `crashed_life`, `clean_life`) and the read-cache encoders, which are crate-private. It calls only public functions of `Storage` and the public `reads` functions, the way the server does. It does **not** reuse `model_tests::observe`: those functions are `pub(super)` and widening them would conflict with M1 and M6 branches; copy the call shapes.

### `golden_tests/build.rs`

```rust
/// Writes the golden scenario into `dir` (must not exist). Deterministic: the same
/// ids, times and bytes every run, except what the storage itself generates
/// (file ids, `created_at`, `registered_at`), which `expected.json` never contains.
pub(super) fn build(dir: &Path);
```

The config is built like `model_tests::harness::model_config` (read it, copy the shape; it is `pub(super)` there): `min_free_bytes` 0, local objects, `wal.sync = Always`, `flush.max_age` 1 h, **`compaction.interval`, `gc.interval` and the deletion interval at 1 h** so no background task changes the directory while the scenario runs, `compaction.l0_files` 2.

Steps (a `clean_life` ends with `shutdown`):

1. **Life 1** (`clean_life`). Spans and scores through `append_spans`/`append_scores`, with `flush_now(Duration::from_secs(30))` after each group so each group becomes its own L0 file:
   - `P1`, day `D1`: 3 traces of 3 spans (an LLM span with token counts and a cost, a tool span, a chat root), two traces in the first flush and one in the second; sessions `s-1`, `s-2` and users `u-1`, `u-2` on the spans; one span with `input`/`output` text and an `attributes` map; one trace with an error status.
   - `P1`, day `D2`: 2 traces (one flush).
   - `P2`, day `D1`: 2 traces; `P2`, day `D0`: 1 trace (the retention step removes it).
   - `P3`, day `D1`: 1 trace (the drop step removes it).
   - scores: for `P1`, 4 scores (numeric, boolean, categorical, one with a comment) on two of its traces and one on a span, a later update (same `score_id`, later `created_at`), one score deletion (read `score_row`'s signature for how); `P2`: 1 score.
   - `put_media(P1, MediaBlob { … })`: a 16-byte blob, `mime_type` `"image/png"`, `newest_span_start` = a `P1` span start.
   - `ingest_time` is chosen by the generator, and no `(trace_id, span_id)` repeats: no duplicates, so reads before and after compaction agree.
   - A fixed clock `NOW` = 2026-02-12T00:00:00Z (ns) for every `compact` and `apply_deletions` call.
2. **Life 2** (`clean_life`, maintenance): `compact(NOW)` until the `CompactionReport` is empty (`P1` day `D1` becomes an L1 spans file and an L1 traces file; `D2` stays L0). Then `collect_obsolete(Duration::ZERO)` removes the replaced L0 files.
3. **Deletions** (same life): `register_deletion` of a trace deletion for one `P1` trace and `apply_deletions(NOW)` (applied); then a user deletion for `u-2` in `P1` that is **not applied** (pending).
4. **Retention and drop** (same life): `apply_retention(P2, D1)` (`D0`'s files become obsolete and stay so: **no GC after it**, so the catalog keeps `state = 'obsolete'` rows and their objects), `drop_project(P3)` (a `projects` row).
5. End the life with `shutdown`. Assert with literals: no `catalog.db-wal` and no `catalog.db-shm` in the directory (the connection closed cleanly); otherwise stop with a message that says so.
6. **Life 3, the WAL tail** (`crashed_life`, dropped without `shutdown`, D-R-4): append to `P1` day `D2` one trace of 2 spans and 2 scores; no `flush_now`. Assert that the spans WAL holds records after `flushed_seq` (count with `wal::replay` into a counter and read `table_state` with `sqlx`).
7. **Cache entry.** Write `cache/<name>/size` and `cache/<name>/0` through the read cache's own encoders (`read_cache::encode_size` and the block writer used with `write_renamed`; read `read_cache.rs` around them), for the object name `tables/spans/golden-cache.parquet` and 4,096 bytes of the pattern `byte(i) = (i % 251) as u8`. About 4 KiB.
8. **Clean the tree**: remove `LOCK` and `tmp/`; keep `wal/`, `objects/`, `cache/`, `catalog.db`.

- `every_golden_directory_is_released_or_unreleased`: every directory other than `unreleased` is listed in `RELEASES`.
- `unreleased_is_gone_once_something_is_released`: if `RELEASES` has a version line, `unreleased/` does not exist.
- Do **not** write a test that the current workspace version is listed: the release commit is the one that adds it, and `release-verify` checks it (§ Requests).

### `just golden-dir` for a release

Replace the recipe body:

```just
golden-dir name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    out="$root/fixtures/storage/golden/{{name}}"
    if [ "{{name}}" = unreleased ]; then
        if grep -qv '^#' "$root/fixtures/storage/golden/RELEASES"; then
            echo "golden-dir: a release exists, so unreleased is no longer allowed" >&2; exit 1
        fi
        rm -rf "$out"
    elif [ -e "$out" ]; then
        echo "golden-dir: $out exists; a released directory is never rewritten" >&2; exit 1
    fi
    LLMOBS_GOLDEN_OUT="$out" cargo test --workspace --all-features -- --ignored --exact golden_tests::write_golden_dir
    case "{{name}}" in
        unreleased|scratch*) ;;
        *) echo "{{name}}" >> "$root/fixtures/storage/golden/RELEASES"
           rm -rf "$root/fixtures/storage/golden/unreleased" ;;
    esac
```

### `just check-golden`

Fails when a branch deletes a released golden directory or removes a line of `RELEASES`:

```just
# Released golden directories and RELEASES lines are never removed (spec 03 § 11, D-R-30).
# Skipped without origin/main. LLMOBS_GOLDEN_DROP=1 allows the clean-up at 1.0 (D-R-12).
check-golden:
    #!/usr/bin/env bash
    set -euo pipefail
    if ! git rev-parse --verify -q origin/main >/dev/null; then echo "check-golden: no origin/main, skipped"; exit 0; fi
    if [ "${LLMOBS_GOLDEN_DROP:-}" = 1 ]; then exit 0; fi
    gone="$(git diff --name-only --diff-filter=D origin/main -- fixtures/storage/golden | grep -v '/unreleased/' || true)"
    lines="$(git diff origin/main -- fixtures/storage/golden/RELEASES | grep '^-[^-]' || true)"
    if [ -n "$gone$lines" ]; then
        echo "check-golden: released golden directories must stay (D-R-12):" >&2
        echo "$gone$lines" >&2; exit 1
    fi
```

Add it to the list `just check-rust` runs. CI has a shallow checkout, so it skips there until `ci.yml` fetches `origin/main` (§ Requests); locally it protects `just check`.

## What not to build in M8

- **A migration framework**, a range of readable versions, or a reader for the pre-M8 WAL layout: nothing exists to read yet (D185; no compatibility layers).
- **A per-file Parquet version check at query time** or in `verify_file`: the directory marker comes first (D-R-26).
- **A marker or wipe for the read cache** beyond the pin of `BLOCK` (D-R-32): the cache heals itself, and the first change that needs a wipe adds it.
- **Golden directories for `meta.db`**, the backup `manifest.json` or the OTLP fixtures: other tracks.
- **A real older binary in CI** opening a newer directory: the synthetic newer directories of R8.7 test the refusal.
- **Archive formats** (`tar.zst`) for the golden directories (D-R-29).

## Open questions for the user

1. **Decision numbers.** D-R-25 is the M3 branch's (WAL decode bounds); M8's decisions are numbered D-R-26 to D-R-32 to avoid a clash. Renumber on merge if M3 numbered differently.
2. **Pre-release directories.** The plan refuses a directory written before M8 (no marker, or a headerless WAL) with a clear message, instead of adopting it. This forces anyone with a local dev directory (the soak machine, `llmobs-data/`) to start a new one when M8 merges. Adopting would need a WAL reader for the old layout, which D185 and "no compatibility layers" argue against. Confirm.
3. **A committed `unreleased` golden directory now** (a canary that every pre-tag format change must regenerate), or none until the first release? The plan commits one; the cost is a regeneration with each format change before the tag.
4. **Plain directory trees instead of `tar.zst`** (a deviation from `00-design.md` and the D-R-12 wording): no new dependencies, reviewable file list, git deduplicates. Accept?
5. **Size budget:** at most 1 MiB per golden directory (test-enforced), target under 300 KiB, one per stable release, 0.x ones kept until 1.0. Is about 1 MiB per release acceptable for the repository?
6. **Pre-releases:** golden directories only for stable releases; the rc dry runs (private drafts, D-N-6) get none. Confirm, since D185 says the rule starts at the first *public* tag.
7. **Parquet version enforcement:** the `llmobs.format_version` key is written and checked only by tests; no query-time check, because the directory marker precedes any read. This leaves a bucket restored under a different catalog unchecked. Acceptable?
8. **`meta.db`** and the other server-side formats are outside M8. Should the server track get a matching plan (golden `meta.db`, refusal of a newer one) before the first tag?
9. **CI history:** `just check-golden` only works in CI once `ci.yml` fetches `origin/main` on pull requests. Until then deleting a golden directory is caught only by the local `just check` and by the test that every `RELEASES` line has a directory.
