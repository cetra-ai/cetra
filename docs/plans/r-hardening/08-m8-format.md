# R · M8 — Format stability

The eighth and last milestone of track R (`00-design.md` § M8, decisions D-R-12 and D185, refined by D-R-26 to D-R-32). From the first public release tag on, a data directory written by one release must open with every later one, and a directory written by a *newer* binary must be refused by an older one without being touched. M8 builds the tools that make both checkable, and lands before that tag:
- **Version markers** where a persisted format has none: the `catalog.db` data-directory marker, a header in every WAL segment, a `llmobs.format_version` key in every Parquet file.
- **Clean refusals** for a newer directory, a newer WAL segment and an unknown catalog migration. Today an older binary truncates a newer WAL tail as if it were torn, or quarantines a newer Parquet file as corrupt.
- **Golden data directories**, small, generated by one tool from the current build, committed from the first stable tag on (before it, the test generates one into a temp dir and checks that), and opened by a test with the current code, whose reads must equal the ones recorded when the directory was written.
- **A release rule**: every stable release adds a golden directory and keeps the old ones (the 0.x ones until 1.0, D-R-12).
- **Catalog migration tests** and **pins** for the read cache and object layout.

Sub-phases R8.1–R8.8, one commit each.

**Before the first public tag there is no format constraint** (D185, `AGENTS.md`). M8 changes formats freely, including the WAL segment layout (R8.3). Directories written before M8 are not migrated: the new code refuses them with a clear message (R8.2, D-R-27; the user confirmed the refusal). **Stored datasets are pre-M8 directories too:** `crates/storage/tests/trace_bench.rs` (around line 705) reuses a stored `catalog.db` dataset, and M7's soak and benchmark directories are built the same way. After M8 they fail with `PreFormat` until regenerated (R8.2 fixes `trace_bench`; the M7 soak tooling and any dataset kept on the soak machine are regenerated by whoever runs them, and the report says so).

## What exists today (checked on `main` 30bed18, and `claude/r-m3-fuzzing`)

Every persisted format, its version marker, and what a reader does with a version it does not know.

| Format | Where | Marker today | Unknown or newer input today |
|---|---|---|---|
| **WAL segment** | `wal/<table>/<first seq, 20 digits>.wal` (`wal/mod.rs::segment_name`) | **None.** No segment header: a segment is records only (`wal/segment.rs::SegmentWriter::create` writes nothing). The spec 12 sentence "the WAL carries a version byte in each segment header" is not true. | A record with `kind != 1` is `Decoded::Invalid` (`wal/record.rs`). In the **last** segment `replay.rs::scan_segment` treats that as a torn tail and **truncates it** (`truncate_tail`): an older binary erases a newer binary's records. Earlier segments: `WalError::Corrupt` (the open fails), or a skip with `--wal-skip-corrupt`. A payload that is not one batch of the table's current schema is `Corrupt` too (`read_batch`). |
| **WAL record** | inside a segment, `wal/record.rs` | `kind` byte (1 = row batch, 2 reserved). Header 17 bytes (`HEADER_LEN`): `u32 payload_len`, `u32 crc32c`, `u64 seq`, `u8 kind`. Payload: an Arrow IPC stream, LZ4-frame compressed, one batch. Cap: `MAX_PAYLOAD` 256 MiB. | As above. On `claude/r-m3-fuzzing` (to merge before M8): `MAX_DECODED_BYTES` 1 GiB declared decompressed bytes per record, LZ4 ratio bound 256 plus 64 bytes of slack per buffer, **LZ4_FRAME only** (D-R-25 there). These are part of what a v1 record is. |
| **Parquet file** | `objects/tables/<table>/project=<id>/day=<YYYY-MM-DD>/<level>-<uuidv7>.parquet` (`objects.rs::table_file_path`) | KV metadata written by `parquet.rs::file_metadata`: `llmobs.table`, `llmobs.schema_version` (`"1"`), `llmobs.level`, `llmobs.min_time`, `llmobs.max_time`, `llmobs.min_ingest_time`, `llmobs.max_ingest_time`. **`llmobs.schema_version` is the row normalization version (spec 01), not a file-format version.** | **No code reads any of these keys** (the catalog holds the same bounds). Extra columns are ignored by DataFusion's schema adapter (spec 03 §3). A changed column type or a missing required column is a read error, which makes the file a suspect (`verify.rs::may_be_corrupt`); `verify_file` then finds it corrupt and **quarantines it**: a newer file that is not corrupt would be hidden from queries. |
| **`catalog.db`** | `<data_dir>/catalog.db`, SQLite WAL mode, `synchronous=FULL` | `sqlx` migrations `0001`–`0007` in `crates/storage/migrations/catalog/`, tracked in `_sqlx_migrations` (version, checksum). Copies keep their number: `catalog.db.pre-m<N>` (`catalog/db.rs::pre_migration_copy`, D-N-22). | An applied migration the binary does not know: `sqlx` `MigrateError::VersionMissing`, so the open fails with `CatalogError::Migrate` and a message about a missing migration, before any write (no pre-migration copy: `applied >= expected`). An edited migration file: `VersionMismatch` (checksum). A TEXT value the binary does not know (`data_files.state`, `table_name`, `deletions.kind`, `projects.state`): `CatalogError::Corrupt` while loading. **No marker for a change that adds no migration**, such as a new meaning for a column. |
| **Catalog snapshot** | `Storage::snapshot_catalog` (`snapshot.rs`), `VACUUM INTO` | Same as `catalog.db`. | Same. The backup `manifest.json` is track N's, not storage's. |
| **Object paths** | `data_files.path` (relative path, never parsed), `media/<project>/<sha256 hex>` (`objects.rs::media_path`) | None. | A path is opaque to readers; a *new layout* only applies to new files. |
| **Media blob** | `objects/media/...`, the raw bytes; `media` table holds mime, size, times | None. | None needed: the blob is the bytes. |
| **S3 read cache** | `cache/<file name>/size` (8 bytes LE size, then CRC-32C: `SIZE_FILE_LEN` 12, D-R-21) and `cache/<file name>/<block index>` (block bytes then CRC-32C) (`read_cache.rs`) | None. Block size `BLOCK` = 1 MiB is implicit. | A `size` file that does not parse drops the whole directory, a bad block CRC drops the block: the cache heals itself. **A changed `BLOCK` would not be detected**: old blocks keep valid CRCs and would be served at the wrong offsets. |
| **`LOCK`, `tmp/`, `admin.sock`** | | no content that survives a restart | not formats |
| **`meta.db`, `secret.key`, backup `manifest.json`** | server and track N | their own | out of M8 (§ Requests) |

Two consequences drive the design:
1. An older binary can **destroy** newer data in two places (WAL tail truncation, quarantine of a newer Parquet file), not only fail to read it. A refusal must therefore come before either can happen: at the first step of `Storage::open`, from a marker in `catalog.db`.
2. `Storage::open` always opens `catalog.db` first (`open_shared` → `Committer::open` → `open_catalog_db`, also for `Maintenance::open`), so one marker there covers every surface of the directory.

## The design

**One number, three places** (D-R-26). `FORMAT_VERSION: u16 = 1` in a new `crates/storage/src/format.rs`. It is the format version of the whole data directory: it changes when *any* persisted surface changes in a way that is not additive. It is written to:
- `catalog.db`'s `PRAGMA user_version` (the directory's **high-water mark**: the highest format any file of the directory may use; a binary writes it before it first writes anything in a newer format, and never lowers it);
- every WAL segment, in an 8-byte header;
- every Parquet file, as KV key `llmobs.format_version`.

`llmobs.schema_version` keeps its meaning (row normalization). The read cache and `tmp/` carry no version (D-R-32).

**Open order.** `open_catalog_db`: connect, read `user_version`; if it is above `FORMAT_VERSION`, fail with `CatalogError::FormatTooNew`. This is before `pre_migration_copy` and before the migrations, so a newer directory is not touched. Then migrate (a migration the binary does not know becomes `CatalogError::SchemaTooNew`). Then, if `user_version` is 0: an empty catalog is a new directory and gets stamped; a non-empty one is a pre-release directory and fails with `CatalogError::PreFormat`. The WAL is read after the catalog (`lib.rs::open_inner`, `recover_tables`), where each segment header is checked.

**What is a format change** (D-R-12, here made concrete):
- **Not a format change:** a new nullable Parquet column; a `catalog.db` migration that only adds (`CREATE TABLE`, `CREATE INDEX`, `ALTER TABLE … ADD COLUMN` with a default or nullable); new config keys.
- **A format change (bump `FORMAT_VERSION`):** a new or changed WAL `kind`, header or compression; a changed IPC schema of a WAL payload; a changed Parquet column type, sort order, KV key meaning or file layout; a renamed or re-typed catalog column, a dropped table, an `UPDATE` of existing rows, a new value of a TEXT enum column (`state`, `kind`, `table_name`); a changed object path layout; a changed checksum; a changed read-cache block size.

**What a release that changes a format must do** (D185, D-R-12): bump `FORMAT_VERSION`, keep a reader for what the previous release wrote (replay of older WAL segments before writing the new ones; Parquet readers for older files, which are never rewritten at upgrade, `docs/self-hosting/upgrade.md`; a catalog migration), test it by the previous releases' golden directories, and add a line to `CHANGELOG.md` § `### Upgrade notes`. The *first* bump is the first time a reader for an older version exists: R8.2 and R8.3 write the checks as "equal to `FORMAT_VERSION`", and that change turns them into a supported range. M8 does not add range code that has nothing to read.

**Downgrade** (D-R-27): a binary that sees a newer marker, a newer WAL header version or a migration it does not know refuses to open, names what it found and what it reads, and changes nothing in the directory. `--wal-skip-corrupt` never bypasses these. There is no downgrade path; the way back is the pre-upgrade backup (`docs/self-hosting/upgrade.md`).

**Golden directories** (D-R-29, D-R-30). `fixtures/storage/golden/<version>/` is a plain directory tree (no archive, so no new dependency), written by the ignored in-crate test `golden_tests::write_golden_dir` through `just golden-dir <version>`. `fixtures/storage/golden/RELEASES` lists the released versions. Each directory holds a real data directory (`catalog.db`, `wal/`, `objects/`, a small `cache/` entry) and `expected.json`. A test opens a temp copy of each one with the current code and compares its reads with `expected.json`.

## R8.2 — The data-directory marker in `catalog.db`

Commit: `storage: refuse a data directory of a newer format, stamp new ones (R8.2)`

Depends on: R8.1.

### New `crates/storage/src/format.rs`

```rust
//! The format version of the data directory (spec 03 § 12, D-R-26).

/// The format version this build writes and reads.
///
/// It changes when any persisted surface changes in a way that spec 03 § 12
/// calls a format change. Today a reader accepts exactly this version; the first
/// bump adds the readers of the previous one.
pub(crate) const FORMAT_VERSION: u16 = 1;
```

`lib.rs`: `pub(crate) mod format;` next to the other modules. The `tests_support` module with `dir_digest` (see Names) lives in the same file.

### `error.rs`: three `CatalogError` variants

```rust
/// The directory was written by a newer format (spec 03 § 12).
#[error("this data directory has format version {found}, which this build (format {supported}) does not read; run the newer release, or restore the backup taken before the upgrade")]
FormatTooNew { found: i64, supported: u16 },
/// A directory from before format versions existed (pre-release).
#[error("this data directory has no format version: it was written before format versions were introduced; create a new data directory")]
PreFormat,
/// `catalog.db` has applied a migration this build does not have.
#[error("catalog.db has applied migration {version}, which this build does not have; run the newer release, or restore the backup taken before the upgrade")]
SchemaTooNew { version: i64 },
```

With doc comments on the fields, like their neighbours. `OpenError::Catalog` is `#[from] CatalogError`, so they reach the caller unchanged.

### `catalog/db.rs::open_catalog_db`

New order, after `connect()`:

1. `let marker = read_user_version(&mut connection).await?;` (`PRAGMA user_version`, an `i64`).
2. `if marker != 0 && marker != i64::from(FORMAT_VERSION)` return `FormatTooNew { found: marker, supported: FORMAT_VERSION }`. No older version exists, so any other value (a newer one, or a corrupt negative one) is refused the same way. This is **before** `applied_version`, `pre_migration_copy` and `migrate`: nothing is written.
3. `let applied = applied_version(..)`. `if marker == 0 && applied > 0 && catalog_has_data(&mut connection).await?` return `Err(PreFormat)`. **Still before `pre_migration_copy` and `migrate`**: a refused pre-release directory is not copied or migrated.
4. `expected`, `pre_migration_copy` and `migrate` as today, with one change: `MigrateError::VersionMissing(version)` becomes `CatalogError::SchemaTooNew { version }`; every other migrate error stays `CatalogError::Migrate`.
5. `if marker == 0`: run `PRAGMA user_version = <FORMAT_VERSION>` (the catalog is new or empty).

`catalog_has_data`: the tables of an old catalog may be missing (migrations are not run yet), so it lists the names in `sqlite_master` first and runs `SELECT EXISTS(SELECT 1 FROM <t>)` only for those present among `data_files`, `deletions`, `media`, `projects`, `retention_watermarks`, plus `SELECT EXISTS(SELECT 1 FROM table_state WHERE flushed_seq > 0)` when `table_state` exists. The empty case matters: a process that dies between the migrations and the stamp of a new directory must be able to open it again, and an old empty catalog that has migrations pending is stamped after it migrates.

`PRAGMA user_version = N` takes an integer literal, not a bound parameter: `format!` the `u16` constant into the SQL. It runs on the single connection outside any transaction, and `synchronous=FULL` makes it durable.

**Why `user_version` and not a table:** it is in the SQLite file header, so it can be read before any migration, it survives `VACUUM INTO` (snapshots and pre-migration copies keep it; tested below), and `sqlite3 catalog.db 'PRAGMA user_version'` shows it to an operator.

## R8.3 — The WAL segment header

Commit: `storage: add a format header to every WAL segment (R8.3)`

Depends on: R8.2, and M3 merged. **A format change, allowed before the first release** (D-R-12, D-R-28): segments written before this commit have no header and are refused (`NotAWalSegment`).

### Layout (spec 03 § 1)

An 8-byte header, then the records, which are unchanged:

```
[0..4)  magic   b"LWAL"
[4..6)  u16 LE  format version (FORMAT_VERSION)
[6..8)  u16 LE  flags, must be 0
[8..)   records (u32 payload_len | u32 crc32c | u64 seq | u8 kind | payload)
```

The record layout is **v1 as it stands after M3**: payload at most 256 MiB, at most 1 GiB declared decompressed bytes per record, each LZ4 buffer's declared size at most 256 times its compressed length plus 64, LZ4-frame compression only, `kind` 1 only. Offsets in errors and logs stay file offsets (they now start at 8).

### `wal/segment.rs`

```rust
/// First bytes of every segment.
pub(crate) const SEGMENT_MAGIC: [u8; 4] = *b"LWAL";
/// Length of the segment header.
pub(crate) const SEGMENT_HEADER_LEN: usize = 8;

/// The header this build writes.
pub(crate) fn segment_header() -> [u8; SEGMENT_HEADER_LEN];

/// What a segment's first bytes say.
#[derive(Debug, PartialEq, Eq)]
pub(crate) enum HeaderState {
    /// A complete, supported header.
    Valid,
    /// Fewer than `SEGMENT_HEADER_LEN` bytes, all equal to the start of the header:
    /// a crash created the file before its header was complete.
    Torn,
}

/// Checks `bytes` (the whole file, or its first bytes) against the header.
///
/// Errors: `WalError::Header` with `NotAWalSegment` (the magic differs, or the file
/// is shorter than the header and is not a prefix of it), `NewerFormat { found, supported }`
/// (the version is not `FORMAT_VERSION`; no older version exists, so the name says newer and the message does not) or `UnknownFlags`.
pub(crate) fn check_header(table: &'static str, segment: &str, bytes: &[u8]) -> Result<HeaderState, WalError>;
```

`SegmentWriter`:
- `create` writes the header with `write_all` through `fs::File` right after opening, then **`sync_data` on the file, then `fs::sync_dir(dir)`** (the existing order of `create`, with the file sync added before the directory sync). The `WalWrite` and `WalSync` hooks are **not** consulted: they model record writes, and a hook that fails the first group must not fail creation. A failing header write or sync is `WalError::io("writing WAL segment" / "syncing WAL segment", …)`, and the rotation path removes the stray file as it does for a failed directory sync (`remove_stray_segment`). `len` starts at `SEGMENT_HEADER_LEN`.
- **Why the sync is required.** In interval mode a segment's records are acknowledged before their `fdatasync`. Without a synced header, a lossy crash that keeps a later record but drops the unsynced header leaves 8 zero bytes then a valid record: the segment fails the header check and the open is refused, losing a directory that only lost unsynced data. With the header synced at creation, a power loss can only cut a segment inside its records.
- `open_segment` reuses an existing file only when it holds no record: its length is at most `SEGMENT_HEADER_LEN` and its bytes are a prefix of the header. A **complete valid header is left untouched** (the opening writes nothing: `model_tests/resources/disk_full.rs` around line 240 relies on an open that needs no space). Only a file **shorter than the header** is truncated to 0, rewritten with the header and synced (same sync as `create`, before the directory sync). Anything else is the error it is today.
- New `pub(crate) fn has_records(&self) -> bool { self.len > SEGMENT_HEADER_LEN as u64 }`.

`wal/writer.rs`: the places that meant "empty segment" by `len() == 0` now mean "holds no records":
- `run`: `let wanted = segment.len() > 0;` becomes `segment.has_records()`.
- `remove_stray_segment`: the file may be removed when its length is at most `SEGMENT_HEADER_LEN`. The "the segment is not empty" error stays for longer files.
- the test near `writer.rs:1327` (`entry.metadata().unwrap().len() > 0`) becomes `> SEGMENT_HEADER_LEN as u64`; every other test that counts bytes or non-empty segments is found by `grep -n "len()" crates/storage/src/wal/writer.rs` and fixed the same way.

`wal/replay.rs::scan_segment` (it has `table` and the segment name through `Scan`). Every test that reads or crafts a segment is affected: see the list below.
1. Call `check_header(scan.table.name(), scan.name, bytes)` first.
   - `Err` → return it. **Header errors are never skipped**, whatever `skip_corrupt` says, and never truncated.
   - `Ok(Valid)` → start the loop at `offset = SEGMENT_HEADER_LEN`.
   - `Ok(Torn)` (a zero-length file is `Torn`) → if `scan.is_last`: `truncate_tail(path, 0, bytes.len(), scan)` and `return Ok(false)` (the `create` that follows rewrites the file). If it is **not** the last segment: it holds no records (a header prefix, empty or partial, has none), so **skip it silently** with a `tracing::warn!` line (segment name, length; no content) and `return Ok(true)`. It is *not* corruption, for two reasons found by review. (a) Replay must be idempotent (M3's `wal_replay` fuzz entry replays twice and `expect`s the second to succeed): a torn last segment named 5, replayed with `after_seq` 9, is truncated to 0 bytes, `create(10)` then makes a newer file, and the second replay sees a 0-byte non-last segment. (b) A rotation whose `SegmentWriter::create` failed in `IoJob::commit` (`writer.rs` around 386-420) leaves a stray file named `next_seq`; only `rotate()` removes strays (`remove_stray_segment`, around 601-618), so after a restart a later name can exceed the stray's and it is non-last with 0 or a partial header. Only a non-last segment with bytes **past a complete valid header** that are damaged goes to `skip_rest`/`Corrupt`, as today.
2. Everything after is unchanged.

`recover_table` and `lib.rs` need no change: the `SegmentWriter::create` after replay already starts a fresh segment. `lib.rs::replay_error` leaves `WalError::Header` as `OpenError::WalReplay`.

   - **Pinned values.** `ingest_time` is chosen by the generator and is `D1 midnight + n seconds` (days earlier than `NOW`), no `(trace_id, span_id)` repeats (no duplicates, so reads before and after compaction agree). `NOW` = 2026-02-12T00:00:00Z (ns) for every `compact` and `apply_deletions` call. `Deletion.cutoff` is a fixed value **at or after the largest `ingest_time`** of the rows in scope (`DeletionScope` covers rows with `ingest_time <= cutoff`), so the deletions hit exactly the rows the scenario means them to. Deletion ids are fixed UUIDs.
2. **Life 2** (`clean_life`, maintenance): `compact(NOW)` until the `CompactionReport` is empty (`P1` day `D1` becomes an L1 spans file and an L1 traces file; `D2` stays L0). Assert an L1 file exists. Then `collect_obsolete(Duration::ZERO)` removes the replaced L0 files.
3. **Deletions** (same life): `register_deletion` of a trace deletion for one `P1` trace and `apply_deletions(NOW)` (applied); then a user deletion for `u-2` in `P1`, **not applied** (pending). `DeletionScope::User` (`deletion.rs` around line 51) carries precomputed `trace_ids` and `session_ids`: get them with the public `user_deletion_scope` read (`reads`), or write the literal lists of `u-2`'s traces and sessions.
4. **Retention and drop** (same life): `apply_retention(P2, D1)` (`D0`'s files become obsolete and stay so: **no GC after it**), `drop_project(P3)` (a `projects` row).
5. End the life with `shutdown`, then call `settle_catalog(dir)` (below).
6. **Life 3, the WAL tail** (`crashed_life`, dropped without `shutdown`, D-R-4): append to `P1` day `D2` one trace of 2 spans and 2 scores; no `flush_now`. Assert that the spans WAL holds records after `flushed_seq` (count with `wal::replay` into a counter and read `table_state` with `sqlx`), and call `settle_catalog(dir)` again.

   **`settle_catalog(dir)`** (a helper in `build.rs`). `Storage::shutdown` and a dropped `Storage` do not call `Committer::close` (only `Maintenance::close` does, `committer.rs` around line 166), and sqlx closes the connection on a worker thread after `clean_life`/`crashed_life` return (`test_support.rs` around 702-727), so an assertion right after a life is racy. It waits up to 5 s for both `catalog.db-wal` and `catalog.db-shm` to disappear; if one is still there it opens a `sqlx` connection on `catalog.db`, runs `PRAGMA wal_checkpoint(TRUNCATE)`, closes it, and then asserts that both are gone. It never stops and reports.
7. **Cache entry.** The read cache names an object's directory by the **file name** of its location (`read_cache.rs` `cached_name`, around lines 708-716), and `ReadCache::open` scans only top-level directories of `cache/` and deletes one whose `size` file does not parse. So: location `tables/spans/golden-cache.parquet`, cache directory `cache/golden-cache.parquet/`. Write it through the cache's own crate-private API: `ReadCache::open(cache_dir, capacity, disk, min_free)` (build the `Disk` the way `read_cache::tests::Fixture`, around line 929, does; if that fixture is private to its test module, add a `#[cfg(test)] pub(crate)` constructor next to it), then `set_size("golden-cache.parquet", 4096)` and `write_blocks("golden-cache.parquet", &[(0, Bytes)])` with 4,096 bytes of the pattern `byte(i) = (i % 251) as u8`. `encode_size`, `write_renamed` and `SIZE_FILE` are private to `read_cache.rs`: do not call them. About 4 KiB. Make `write_blocks` and `set_size` `pub(crate)` if they are not.
8. **Clean the tree**: remove `LOCK` and `tmp/`; keep `wal/`, `objects/`, `cache/`, `catalog.db`.

### `golden_tests/dump.rs`

```rust
/// The answers of the public reads over the golden scenario, as JSON.
/// Called on a COPY of the directory only (see `check_dir` and `write_golden_dir`).
pub(super) async fn dump(storage: &Storage) -> serde_json::Value;
```

**A dump never runs on the committed or freshly built directory itself**: `Storage::open` creates a new WAL segment and `shutdown` flushes the WAL tail, which would remove the tail the directory exists to keep. `write_golden_dir` builds into `out`, copies `out` to a temp dir, opens and dumps the copy, and writes `expected.json` into `out`. `build_is_deterministic` and the other tests do the same.

It calls `trace_list`, `trace_detail`, `span_list`, `score_list`, `latest_scores`, `session_list`, `user_list`, `metrics`, `deletion_status` and `get_media` with the request values `model_tests/observe.rs` uses (`observe_traces`, `observe_trace_detail`, `observe_spans`, `observe_scores`, `observe_latest`, `observe_sessions`, `observe_users`, `observe_kpis`). Always an explicit `TimeWindow` of `[D0 midnight, D2 midnight + 1 day)`, never the clock; every page followed; sorted deterministically (sort again where the read does not order).

Keys of the JSON:

```
format_version        FORMAT_VERSION at generation
workspace_version     CARGO_PKG_VERSION at generation (added in R8.8)
generator             1 (the version of this scenario and file; frozen, see below)
windows               {"from": ns, "to": ns}
write_probe           {"project": P1, "day": "2026-02-11", "start_time": ns}   where check_dir adds one trace
projects[<P1|P2>]     traces (id, name, start, end, span_count, error, tokens, cost, session, user),
                      trace_details[<trace id>] (span ids, parent, name, kind, status, model, tokens),
                      spans, scores, latest_scores, sessions, users, kpis
dropped[<P3>]         trace_list is empty
deletions             statuses by the generator's fixed deletion ids: applied, pending
media                 {"project": P1, "sha256": hex, "bytes_len": 16}
catalog               data_files counts grouped by (table, level, state), retention watermarks, projects rows
                      (id, state), media rows (id, mime, size), number of applied migrations.
                      Not flushed_seq, file ids or timestamps (storage-assigned).
cache                 {"name": "golden-cache.parquet", "location": "tables/spans/golden-cache.parquet", "size": 4096}
```

`catalog` comes from `catalog_summary(dir) -> serde_json::Value` in `dump.rs`: a `sqlx` connection on a **copy** of `catalog.db`, run before `Storage` opens the directory.

**The scenario is frozen from the first release on.** A later change to what `build` writes is a new `generator` number with the new code path added beside the old; the check accepts every `generator` it finds in `fixtures/storage/golden/`. New keys in `expected.json` are optional on read (`Value::get`).

**Amending a released `expected.json`.** A released directory and its `expected.json` are never rewritten, with one exception: a released build's answer is proven wrong (a bug in a read), so the recorded value was wrong. The amendment is its own commit, explains the bug, and adds a line under `### Upgrade notes` in `CHANGELOG.md` when the answer a user sees changes.

### Tests (`golden_tests/mod.rs`)

- **Speed.** Each build is three lives, a dump is about 25 DataFusion queries and `check_dir` dumps twice; CI's `just test` has a 45-minute limit. So the fresh directory is built **once per process**: `static FRESH: OnceLock<tempfile::TempDir>` in `golden_tests/mod.rs` (built on first use, with its `expected.json`), and every test copies from it. Only `build_is_deterministic` builds a second one. Each new test reports its run time; the target is a few seconds each. If a dump is slower than that, trim it (fewer pages, fewer reads) rather than skipping a read.
- A recursive directory-copy helper (`crate::fs` has none) lives in `test_support.rs` as `pub(crate) fn copy_dir(from, to)` and is used by `check_dir`, `a_newer_golden_directory_is_refused` and the cache test.
- `build_is_deterministic`: `build` a second time into another temp dir, copy it, `dump` the copy (in a `clean_life`) and compare with the first one's `expected.json`: equal.
- `build_leaves_the_expected_shape`: the temp dir has `catalog.db`, no `-wal` or `-shm`, `wal/spans/*.wal` and `wal/scores/*.wal` (first 4 bytes `LWAL`), at least one L1 and one L0 Parquet file for a live project, one `obsolete` row, one `pending` and one `applied` deletion, one `projects` row, one media row, `cache/golden-cache.parquet/size`, no `LOCK`; every Parquet file under `objects/tables` carries `llmobs.format_version == FORMAT_VERSION` (R8.4's `file_format_version`).
- `write_golden_dir`, `#[ignore = "writes a fixtures directory; run by just golden-dir <version>"]`: reads `LLMOBS_GOLDEN_OUT` (an absolute path that must not exist), runs `build`, dumps a copy, writes `expected.json` (`serde_json::to_string_pretty`, trailing newline) into the directory, prints its size. Share the writing code with R8.7's fresh-directory test.

### Size: measure first

Parquet files of this scenario will be about 20, at 10–30 KB each (bloom filters, page indexes and footers dominate small files), and `catalog.db` at least 100 KB: expect 400–700 KB against the 1 MiB limit. **Before committing the scenario, build it once, report the total size and the largest files, and reduce it if it is over 700 KB**: fewer flush groups (only `P1` day `D1` needs two, so that compaction has something to merge), fewer traces, fewer spans per trace, shorter strings, no `input`/`output` beyond one span. The limit stays 1 MiB.

## R8.7 — The golden test, generate-then-check

Commit: `storage: open every golden data directory with the current build (R8.7)`

Depends on: R8.6.

### `golden_tests/mod.rs::check_dir`

```rust
/// Opens a copy of the golden directory `dir` with the current code and checks it.
/// `dir` is never written: the work happens in a temp copy.
async fn check_dir(dir: &Path)
```

Steps (every assertion message names the directory by its basename and the step). Steps 3 to 5 run **before** the open, because the open collects obsolete files older than `gc.grace` (an aged directory's obsolete files are all older), and the config of `check_dir` is the one of `build` (grace 30 days):

1. Parse `expected.json` (`generator` must be one this code knows: 1).
2. Copy `dir` recursively into a `tempfile::tempdir()`.
3. **Marker**: `PRAGMA user_version` of the copy's `catalog.db` (a `sqlx` connection, closed afterwards) equals `expected.format_version`; every `wal/*/*.wal` starts with `LWAL` and a version equal to it.
4. `catalog_summary(copy)` equals `expected.catalog`.
5. **Files**: every `data_files` row whose state is `active` or `obsolete` has its object under `objects/`; every active Parquet file's footer carries `llmobs.format_version == expected.format_version` (`parquet`'s `SerializedFileReader`).
6. **Open** with `Storage::open(config)`: no error. (A released build's directory must open with every later build.)
7. `dump(&storage)` equals `expected.json` on every key except `format_version`, `workspace_version` and `catalog`. (Reads do not depend on obsolete files, so the open-time GC does not change them.)
8. **New writes on an old directory.** Append to `write_probe.project` one trace of two spans at `write_probe.start_time` through `append_spans`; `flush_now`; `compact(NOW)`; `apply_deletions(NOW)`. Then: the probe trace is readable (`trace_detail`); the `trace_details` of every old trace equal `expected.json`'s; `trace_list` equals `expected.json`'s plus exactly the probe trace; the WAL-tail trace is flushed (a second `dump` after `flush_now` equals the first **plus exactly the probe trace**).
9. `shutdown`.

`expected.format_version` comes from the file, so a directory written by an older release is checked against what *it* recorded.

## R8.8 — The release rule

Commit: `storage: add the golden-directory release rule (R8.8)`

Depends on: R8.7.

### `RELEASES`

Lines are the versions of stable releases (`0.1.0`), not pre-releases (`0.1.0-rc.1`: a private dry run, D-N-6, no golden directory; one may be added by hand and then is listed too).

### `write_golden_dir` and `expected.json`

`dump` gets `workspace_version` (`env!("CARGO_PKG_VERSION")`). `write_golden_dir` refuses to run when `CARGO_PKG_VERSION` differs from the directory's name, unless the name starts with `scratch`: a golden directory is written by the build it is named after (`release-prep` has already set the version).

### Tests (`golden_tests/mod.rs`)

- `every_released_version_has_a_golden_directory`: each version line of `RELEASES` has a directory of that name whose `expected.json` has the same `workspace_version`.
- `every_golden_directory_is_released`: every directory under `fixtures/storage/golden/` is listed in `RELEASES` (a `scratch*` directory fails it: delete it).
- Do **not** write a test that the current workspace version is listed: the release commit is the one that adds it, and `release-verify` checks it (§ Requests).

### `just golden-dir` for a release

```just
golden-dir name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    out="$root/fixtures/storage/golden/{{name}}"
    if [ -e "$out" ]; then
        echo "golden-dir: $out exists; a released directory is never rewritten" >&2; exit 1

    case "{{name}}" in
        scratch*) ;;
        *) echo "{{name}}" >> "$root/fixtures/storage/golden/RELEASES" ;;
    esac
```

### `just check-golden`

Fails when a branch deletes a released golden directory or removes a line of `RELEASES`:

```just
# Released golden directories and RELEASES lines are never removed (spec 03 § 12, D-R-30).
# Skipped without origin/main. LLMOBS_GOLDEN_DROP=1 allows the clean-up at 1.0 (D-R-12).
check-golden:
    #!/usr/bin/env bash
    set -euo pipefail
    if ! git rev-parse --verify -q origin/main >/dev/null; then echo "check-golden: no origin/main, skipped"; exit 0; fi
    if [ "${LLMOBS_GOLDEN_DROP:-}" = 1 ]; then exit 0; fi
    base="$(git merge-base origin/main HEAD)"
    gone="$(git diff --no-renames --name-only --diff-filter=D "$base" -- fixtures/storage/golden || true)"
    lines="$(git diff --no-renames "$base" -- fixtures/storage/golden/RELEASES | grep -E '^-[^-]' || true)"
    if [ -n "$gone$lines" ]; then
        echo "check-golden: released golden directories must stay (D-R-12):" >&2
        echo "$gone$lines" >&2; exit 1
    fi
```

The merge base (not `origin/main` itself) keeps a branch that is behind `main` from being blamed for what `main` added or removed; `--no-renames` makes a moved file show as a deletion. Add it to the list `just check-rust` runs (locally, `just check` covers it). CI does not run `check-rust`: it needs its own step and a fetch of `origin/main` (§ Requests), and skips without them.

## What not to build in M8

- **A migration framework**, a range of readable versions, or a reader for the pre-M8 WAL layout: nothing exists to read yet (D185; no compatibility layers).
- **A per-file Parquet version check at query time** or in `verify_file`: the directory marker comes first (D-R-26; the user confirmed).
- **A marker or wipe for the read cache** beyond the pin of `BLOCK` (D-R-32): the cache heals itself, and the first change that needs a wipe adds it.
- **A committed golden directory before the first stable tag**, or an `unreleased` one (user).
- **Golden directories for `meta.db`**, the backup `manifest.json` or the OTLP fixtures: other tracks.
- **A real older binary in CI** opening a newer directory: the synthetic newer directories of R8.7 test the refusal.
- **Archive formats** (`tar.zst`) for the golden directories (D-R-29).
