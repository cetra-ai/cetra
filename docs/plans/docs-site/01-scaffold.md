### 3. `website/astro.config.mjs`

```js
import starlight from "@astrojs/starlight";
import { defineConfig } from "astro/config";
import starlightLinksValidator from "starlight-links-validator";
import starlightSidebarTopics from "starlight-sidebar-topics";

// The site is cetra.sh: the landing page at `/` (src/pages/index.astro) and the
// documentation under `/docs/` (src/content/docs/docs/), D-W-2.
export default defineConfig({
  site: "https://cetra.sh",
  trailingSlash: "always",
  integrations: [
    starlight({
      title: "cetra",
      description:
        "Open-source LLM observability and evaluation that runs as one binary on one machine.",
      favicon: "/favicon.svg",
      customCss: ["./src/styles/custom.css"],
      social: [{ icon: "github", label: "GitHub", href: "https://github.com/cetra-ai/cetra" }],
      editLink: { baseUrl: "https://github.com/cetra-ai/cetra/edit/main/website/" },
      // CI checks out one commit; git dates would all be the same.
      lastUpdated: false,
      plugins: [
        starlightLinksValidator(),
        starlightSidebarTopics([
          {
            label: "Docs",
            link: "/docs/",
            icon: "open-book",
            items: [{ label: "Overview", link: "/docs/" }],
          },
        ]),
      ],
    }),
  ],
});
```

Notes:
- Only the Docs topic exists now. Integrations, Reference and Self-hosting are added by the phases that write their first page (no empty topic, `AGENTS.md` § No placeholders).
- Check the option names against the installed READMEs (`starlightSidebarTopics` takes an array of topics with `label`, `link`, `icon`, `items` in 0.9.0; `social` is an array in Starlight 0.42). If a name differs, use the README's and note it in the report.
- `starlightLinksValidator()` with its defaults fails the build on a broken internal link or anchor and on a relative link (`errorOnRelativeLinks` defaults to true), which enforces the style guide's absolute links.

### 9. `check-terms.mjs`

`website/scripts/check-terms.mjs` reads every `.md` and `.mdx` file under `src/content/docs/` and fails (exit 1, one line per finding: `path:line: message`) when:

1. a line outside a code fence (``` … ```) matches a banned pattern:
   - `/\bllmobs\b/i` → "the old name (D46)";
   - `/\b(Cetra|CETRA)\b/` → "cetra is lower case" (a match inside inline code, between backticks, is allowed);
   - `/\b(seamless(ly)?|blazing(ly)?|effortless(ly)?|powerful)\b/i` → "marketing word";
   - `/\bsimply\b/i` → "remove 'simply'";
   - `/\bOpen Telemetry\b|\botel\b/` → "write OpenTelemetry or OTel";
   - `/\bon-prem(ise)?\b/i` → "write self-hosted";
2. the frontmatter has no `description`, or its `description` is longer than 160 characters.

Export one function, `checkFile(path, text)`, returning the findings, and a `main` that walks the tree, so the test can call `checkFile` on strings. `website/scripts/check-terms.test.mjs` (`node:test`, `node:assert/strict`) covers: each banned pattern found outside a fence; the same word inside a fence not found; `Cetra` inside backticks allowed; a missing and an over-long description found; a clean file gives no finding.

Use only `node:fs`, `node:path`, `node:url`. The directory walk uses `readdirSync(dir, { recursive: true })`.
