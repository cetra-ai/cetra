### 2. The attribute page and its test

**`reference/attributes.md`** (title "Span attributes"). Sections:
- "cetra attributes": a table `| Attribute | Type | Set by | Meaning |` with every user-facing span attribute constant of `crates/core/src/names.rs` (the `cetra.*` names the SDKs set and the normalizer reads: span kind, input, output and their formats, session, user, tags, `cetra.metadata.<key>`, environment, release, TTFT, cost, experiment and dataset item IDs). Attributes the server writes on its own spans (evaluation, normalization warnings) go in a second table "Set by cetra", with a sentence saying users never set them.
- "Conventions cetra reads": per convention (OpenTelemetry GenAI, OpenInference, OpenLLMetry, Vercel AI SDK, Langfuse, Laminar, Google ADK) a table of the attributes cetra maps and the cetra field each feeds, from spec 02 § Conventions. Only attributes spec 02 names.

The test, in `crates/core/src/names.rs` `mod tests`:

```rust
#[test]
fn the_attribute_reference_names_every_cetra_attribute() {
    let page = include_str!(concat!(
        env!("CARGO_MANIFEST_DIR"),
        "/../../website/src/content/docs/docs/reference/attributes.md"
    ));
    // Every `cetra.`-prefixed attribute written in backticks on the page.
    let documented: std::collections::BTreeSet<&str> = page
        .split('`')
        .skip(1)
        .step_by(2)
        .filter(|token| token.starts_with("cetra."))
        .collect();
    // ATTRIBUTES lists the constants this test covers; see the note below.
    let expected: std::collections::BTreeSet<String> = ATTRIBUTES
        .iter()
        .map(|name| if name.ends_with('.') { format!("{name}<key>") } else { (*name).to_owned() })
        .collect();
    let expected: std::collections::BTreeSet<&str> = expected.iter().map(String::as_str).collect();
    assert_eq!(documented, expected);
}
```

`ATTRIBUTES` is a `const ATTRIBUTES: &[&str]` in the test module that lists every `cetra.`-valued attribute constant of `names.rs` by path (`attr::SPAN_KIND`, …). Read `names.rs` and include every constant whose value starts with `cetra.`, in every module of the file; prefixes (`METADATA_PREFIX`, ending in `.`) are written `cetra.metadata.<key>` on the page. Add a comment above `ATTRIBUTES`: "A new attribute constant joins this list and the site's attribute page (D-W-7)." If the crate's lints refuse `include_str!` of a path outside the crate, stop and report.

### 4. Concepts pages

Each page: frontmatter, a one-sentence opening, then the required sections. Sources in README § Page list.

- **`concepts/data-model.mdx`** "Data model": org → project → (environments); trace, span, span kinds (table of each kind with one line); session; user; score (attached to a trace, span or session); dataset and dataset item; experiment; IDs and timestamps (16-byte trace IDs and 8-byte span IDs as hex, nanoseconds). One diagram as a Mermaid-free ASCII tree in a `text` fence.
- **`concepts/how-cetra-works.mdx`** "How cetra works": the path of a span: OTLP in → normalization (conventions, payloads, media, truncation, cost) → write-ahead log (acknowledged = durable) → in memory → Parquet files (local disk or S3) → queries (the UI, API, SQL console and MCP read the same data) → evaluation and alerts on top; the metadata database for users, keys and settings; one process, one data directory. Explain what "acknowledged" means for the SDKs. No numbers (D-W-14). Link to Self-hosting › Resources for sizing.
- **`concepts/conventions.mdx`** "Semantic conventions": why conventions matter; the table convention → how to recognise it → what cetra reads → integration page (W8 links; until W8, no link); precedence when a span carries several; what happens to unknown attributes (kept as attributes, searchable). Link `/docs/reference/attributes/`.
- **`concepts/glossary.mdx`** "Glossary": STYLE.md's terminology as definitions, alphabetical.
