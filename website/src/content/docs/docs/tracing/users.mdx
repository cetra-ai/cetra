Set a user ID on your traces to see what each of your users does and costs.

A user is an end user of your application. cetra builds the user list from the user IDs on your traces. See the [data model](/docs/concepts/data-model/).

## Set a user ID

Use the same context block as for sessions. Every span started inside it carries the user ID.

<Tabs syncKey="lang">
  <TabItem label="Python">

{/* test */}
```python
import cetra

cetra.init()


@cetra.observe(name="turn")
def turn() -> None: ...


with cetra.context(user_id="u-17", session_id="chat-42"):
    turn()

cetra.flush()
```

  </TabItem>
  <TabItem label="TypeScript">

{/* untested: the imports line is part of the example below */}
```ts
import { observe, withContext } from "@cetra-ai/sdk";
```

{/* example:with-context */}
```ts
const turn = observe(({ question }: { question: string }) => `answered: ${question}`, {
  name: "turn",
});
withContext({ sessionId: "chat-42", userId: "u-17", tags: ["beta"] }, () =>
  turn({ question: "why?" }),
);
```

  </TabItem>
  <TabItem label="Attributes">

Set the attribute `cetra.user.id` on a span. cetra also reads `user.id` and `enduser.id`, and the user attributes of the other [conventions](/docs/concepts/conventions/).

{/* untested: a fragment; the exporter setup is on the Send OpenTelemetry page */}
```python
with tracer.start_as_current_span("turn") as span:
    span.set_attribute("cetra.user.id", "u-17")
```

  </TabItem>
</Tabs>

Use an ID that is stable for a person and that is not their email address or name. cetra shows the ID as you send it, and deletes data by it.

## In the UI

Select **Users** in the sidebar. The list shows each user's traces, sessions, cost, last activity and errors. Open a user to see their sessions and totals.

<Image src={users} alt="The users page: one row per user ID." />

## Filter by user

Filter the traces list with `user_id = 'u-17'`. In SQL, group by `user_id` to rank users by spend. See [SQL console](/docs/tracing/sql-console/).

## Limits

- A trace takes its user from the root span, or from the first span that has one.
- An administrator can delete all the data of a user from the project settings ([Deletion and retention](/docs/platform/deletion-and-retention/)).
