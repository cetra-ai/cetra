Send images, audio and files inside your messages, and cetra stores them next to the trace and shows them in the UI.

Large binary values do not belong in a database row or a filter result. When cetra finds one in a payload, it stores the bytes once and leaves a reference in the span.

## What cetra extracts

cetra looks in the input, output and system instructions of each span, and extracts:

- `blob` parts in messages, which hold base64 data;
- data URIs of the form `data:<type>;base64,<data>` anywhere in a text value;
- the media forms of the provider APIs: OpenAI image URLs and input audio, Anthropic base64 sources, and Gemini inline data;
- image and file parts of the Vercel AI SDK.

A blob is extracted only if it is at least `media.min_bytes` (4 KiB by default). Smaller ones stay in the payload. cetra names the type from the type your span declares. If there is none, it recognizes common formats from their first bytes: PNG, JPEG, GIF, WebP, PDF, WAV, MP3, OGG, FLAC, MP4 and WebM.

## Transcripts

A media part can carry a `transcript`: the text of what was said. For audio, this is the spoken words. Put the transcript on the media part itself, not in a text part next to it:

```json
{"type": "blob", "modality": "audio", "mime_type": "audio/wav", "transcript": "What is my balance?", "content": "<BASE64_DATA>"}
```

cetra keeps the transcript when it stores the media, and when it drops the media for its size. Other details:

- For OpenAI chat completions with audio output, cetra keeps the transcript that the API returns with the audio.
- A message that has no text, only audio, shows its transcripts as its preview.
- Judges read audio with a transcript as `[audio: <transcript>]`. Without a transcript, a judge reads `[audio]`.
- The **Chat** tab plays audio in a player with a waveform, and shows the transcript under the player. The waveform is drawn for files up to 8 MiB. Larger files show a progress bar. If the browser cannot play a file, the player says so, and the transcript still shows.

## Where media is stored

cetra writes each blob once, named by its SHA-256 hash, in the media area of your data directory, or in your S3 bucket if you use one. The same image sent twice is stored once. In the span, the blob is replaced by a `media://<hash>` reference. The UI and API serve it only to signed-in members and keys of the project.

## In the UI

The **Chat** tab of a span shows images and PDFs from their references. Audio plays in a player with a waveform, and its transcript shows under the player. In the raw **Input / Output** tab you see the `media://` reference. Select a media item to open it.

## Size limits

A blob larger than `media.max_bytes` (32 MiB by default) is not stored. cetra replaces it with a reference to `cetra:dropped`, with the reason `too_large` and the size, so you can see that something was there. The rest of the span is kept.

Both bounds are settings of the server. See the [configuration reference](/docs/self-hosting/configuration-reference/). The request size limit of the OTLP endpoint also applies. See [OTLP endpoint](/docs/reference/otlp/).

## Filter

The `media_refs` column of `spans` lists the hashes of a span's media. Filter the spans list with `array_length(media_refs) > 0` to find spans that have media.
