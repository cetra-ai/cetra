Trace IBM watsonx.ai model calls with cetra from Python.

## Install

```bash
pip install ibm-watsonx-ai opentelemetry-instrumentation-watsonx opentelemetry-exporter-otlp-proto-http
```

## Set up

{/* untested: needs an IBM Cloud account */}
```python
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.instrumentation.watsonx import WatsonxInstrumentor
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(
        OTLPSpanExporter(
            endpoint="http://localhost:8080/v1/traces",
            headers={"Authorization": "Bearer <SK_CETRA_KEY>"},
        )
    )
)
trace.set_tracer_provider(provider)
WatsonxInstrumentor().instrument(tracer_provider=provider)

# Call watsonx.ai with ibm_watsonx_ai as usual.
provider.shutdown()
```

Replace `<SK_CETRA_KEY>` with your `sk-cetra-` API key. See [Send OpenTelemetry](/docs/get-started/opentelemetry/).

## What you get

- The OpenLLMetry watsonx instrumentation records model calls with the provider `ibm.watsonx.ai`.
- No built-in price: add a custom model price in Settings → Model prices to get a cost.

## Limits

- Setup only: calling watsonx needs an IBM Cloud account, and no spans are captured.
- No spans of IBM watsonx.ai are captured in the repository. cetra's host table has no watsonx host; the provider `ibm.watsonx.ai` comes from the OpenLLMetry instrumentation.
- The built-in prices have no IBM watsonx.ai rows, so cost is empty until you add a custom model price in Settings → Model prices.
- If a field is missing, look at the span's **Attributes** tab and compare it with [Span attributes](/docs/reference/attributes/).
