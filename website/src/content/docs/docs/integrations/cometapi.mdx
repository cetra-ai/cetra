## Set up

<Tabs syncKey="lang">
  <TabItem label="Python">

{/* untested: calls CometAPI and needs COMETAPI_KEY */}
```python
import os

import cetra
from openai import OpenAI

cetra.init(instrument=["openai"])

client = OpenAI(base_url="https://api.cometapi.com/v1", api_key=os.environ["COMETAPI_KEY"])
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
)
print(response.choices[0].message.content)

cetra.flush()
```

## What you get

- Each chat completion is an `llm` span with the provider `cometapi`.
- Input and output token counts come from the response.
- No built-in price: add a custom model price in Settings → Model prices to get a cost.
- With `cetra.init(instrument=["openai"])`, the endpoint host is in `server.address`, and cetra names the provider from it.

## Limits

- CometAPI resells many publishers' models; the span names CometAPI, and the built-in prices do not apply.
- No spans of CometAPI are captured in the repository. cetra maps the host `api.cometapi.com` to the provider `cometapi`.
- The built-in prices have no CometAPI rows, so cost is empty until you add a custom model price in Settings → Model prices.
- With plain OpenInference or the official OpenAI instrumentation in Python, the provider shows as `openai`: they do not record the endpoint. Use `cetra.init(instrument=["openai"])` or OpenLLMetry.
- If a field is missing, look at the span's **Attributes** tab and compare it with [Span attributes](/docs/reference/attributes/).
