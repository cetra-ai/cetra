A dataset is a versioned collection of inputs, with an expected output when you have one, that you run [experiments](/docs/evaluation/experiments/) on.

## Items

A dataset item has:

- `input`: any JSON value (required);
- `expected_output`: any JSON value (optional);
- `metadata`: an object of your own fields.

A dataset has a name of 1 to 200 characters that is unique in the project, and an optional description. A dataset holds up to 50,000 items, and one item can be up to 1 MiB. Wherever a page or an API route takes a dataset, you can give its name or its ID.

## Versions

Every change to a dataset's items makes a new version: adding a batch, editing or deleting an item, an import, or adding from a trace. A new dataset is at version 0 with no items. A change that changes nothing makes no version.

Reads use the latest version unless you ask for another one. Past versions are read-only. An experiment pins the version it ran on, so you can always compare results with the data they ran against.

## Create a dataset in the UI

1. Open **Datasets** and select **New dataset**.
2. Enter a name, a description and, optionally, JSON Schemas for the input and the expected output.
3. Add items with **Add item**, or import a file.

The **Items** tab edits one item at a time in a side sheet. The **Versions** tab shows the history with a generated description for each version, and **Experiments** lists the experiments run on the dataset.

## Import a file

Import takes a CSV or JSONL file of up to 100 MiB and 50,000 rows.

1. On the dataset page, select **Import**, then choose the file.
2. For a CSV, map each column to a part of the item: `input`, `input.<key>`, `expected`, `expected.<key>`, `metadata.<key>`, or `ignore`.
3. Check the preview, which shows the columns and the first rows, then import.

The column rules:

- A cell that holds a JSON object or array becomes that JSON; any other cell is a string.
- An empty cell leaves its key out.
- A JSONL row can use the keys `input`, `expected_output` and `metadata` directly.
- JSONL rows ignore the keys `id`, `source_trace_id` and `source_span_id`, so an exported file imports back. Any other key is a row error.

The import lists invalid rows (up to 100) and stores the valid ones as one new version. If no row is valid, nothing is imported.

## Export

The **Export** menu downloads a version as JSONL or CSV. Spreadsheet programs may run a cell that starts with `=` as a formula, so check a CSV export before you open it in one.

## Add a trace or a span

On a trace page, **Add to dataset** copies the root of the trace, or the selected span, into a dataset. The span's input becomes the item's input and its output becomes the expected output. You can edit both before you save, and choose an existing dataset or a new one. The item remembers its source trace. If you delete the trace's data, the item is deleted with it.

## Check items against a schema

When a dataset has an input schema or an expected output schema (JSON Schema, draft 2020-12), cetra checks every item written afterwards: added, edited, imported or copied from a trace. A refused item fails the whole request, and the error names the failing fields. Setting a schema on a dataset that has items first checks every existing item.

## Use a dataset from code

The `Client` of each SDK reads the API key and the server URL the way `init()` does: the argument, then `CETRA_API_KEY` and `CETRA_BASE_URL`. It needs a key with the `read` and `write` scopes, and its calls raise an error when they fail.

```python
import cetra

client = cetra.Client()  # the key and URL come from the environment

ds = client.datasets.create("faq-v1", description="FAQ questions")
ds = ds.add_items(
    [
        {
            "input": {"q": "How do I cancel?"},
            "expected_output": {"a": "Settings > Billing > Cancel"},
            "metadata": {"topic": "billing"},
        }
    ]
)
ds = client.datasets.get("faq-v1", version=1)  # the items of version 1
print([info.name for info in client.datasets.list()])
client.datasets.delete("faq-v1")  # the dataset and its items
```

const client = new Client(); // the key and URL come from the environment

let dataset = await client.datasets.create("faq-v1", { description: "FAQ questions" });

- Any key other than the three item fields is refused before a request is sent.
- `add_items` (`addItems` in TypeScript) sends batches of 1,000 items, and each batch makes a new version. It returns the dataset at its latest version. If a later batch fails, the earlier batches stay stored.
- `get` without a version reads the current one.
- `create` also takes `input_schema` and `expected_schema` (`inputSchema` and `expectedSchema` in TypeScript). A refused item raises an `ApiError` whose `errors` list names the failing fields.

The same operations are available over the REST API under `/api/v1/projects/{project}/datasets`:

```bash
curl -H "Authorization: Bearer <API_KEY>" \
  "http://localhost:8080/api/v1/projects/current/datasets/faq-v1/items?version=1"
```
